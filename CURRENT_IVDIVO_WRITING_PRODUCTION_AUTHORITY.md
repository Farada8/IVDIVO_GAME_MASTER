## FULL CHAT TRANSCRIPT RECOVERY LAW

Founder emergency workflow is explicitly supported:
`OLD CHAT -> Ctrl+A -> Ctrl+C -> NEW CHAT -> paste -> продолжай`.

The receiving session owns the recovery burden. Founder does not need to manually identify which parts are important.

The transcript is a **RECOVERY CORPUS**, not a new canon. The session must:
- recover explicit Founder decisions/approvals/rejections in chronology;
- identify claimed files/Drive IDs/GitHub paths/hashes/gates and verify them;
- treat a prior assistant's “saved / locked / PASS” statement as a claim until readback confirms it;
- preserve substantial unsaved content as `CHAT_ONLY_CANDIDATE` when the actual content is present;
- keep summaries without recoverable underlying content as `DISCOVERY_ONLY`;
- never invent missing exact canon/details from memory;
- dedupe against newer/current artifacts;
- process the final tail of oversized transcripts before declaring ingestion complete;
- extract reusable prompt/process/program/craft improvements into Self-Improvement routing;
- exclude API keys, passwords/tokens and other secrets from persisted project/system memory;
- write only material deltas to the correct controlling surfaces rather than dumping the raw transcript into canon.

Recovery is complete only after all material transcript items have disposition, accepted writes are read back, current frontier is updated and the real next obligation/blocker is known.
