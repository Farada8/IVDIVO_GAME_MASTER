## PRIMARY RULE

For any IVDIVO conversation, before substantive work:

1. Read this router.
2. Read `IVDIVO_CONTINUATION_RECOVERY_PROTOCOL_v2.0.md`.
3. Identify the `ACTIVE PROJECT / BOOK / EPISODE / SYSTEM` from the Founder’s current instruction and Project context.
4. Identify the project’s current authority and project-specific operational state (`CURRENT_EXECUTION_STATE`, `DRAFT_STATUS`, current accepted gate/build/release state, or equivalent).
5. Run the mandatory freshness sweep and `STALE_WORK_GATE` before producing new work.
6. Load the correct domain launcher:
   - book/saga: `IVDIVO_NARRATIVE_OS/11_BOOK_CHAT_STARTER.md`;
   - audio: `IVDIVO_AUDIO_NEW_CHAT_BOOT_v3.3.md` plus current Audio Production Authority;
   - other current production systems: their current explicit router/authority.
7. Load relevant Drive working state and File Library/reference sources only as required.
8. Continue the latest valid `ACTIVE / CANON / LOCKED / WORKING` frontier.

Do not silently recreate, rename, replace or supersede accepted work.
Do not let a historical router snapshot override a newer project-specific status artifact.

## FRESHNESS SWEEP — MANDATORY

Before actual work:

1. resolve active line;
2. open active authority/exact source;
3. open current project-specific state;
4. inspect relevant current/recent GitHub `main` project state;
5. inspect Drive `CURRENT_PROMPTS` / `CURRENT_WORKSTATE` + active project working state;
6. inspect new model-specific handoffs;
7. consult File Library/reference books/scripts/research only when materially useful;
8. label uncertainty/status explicitly;
9. run `STALE_WORK_GATE`;
10. identify `LAST COMPLETED / OPEN GATES / BLOCKERS / HIGHEST UNBLOCKED NEXT OBLIGATION`;
11. execute it.

Filename version and filesystem timestamp are not enough by themselves. Explicit authority, project status, accepted gate and source provenance are stronger freshness evidence.

## STALE_WORK_GATE

Do not execute the proposed stage if:

- it is already `PASS / GREEN / ACCEPTED / LOCKED`;
- a newer project-specific `DRAFT_STATUS` / `CURRENT_EXECUTION_STATE` exists;
- it uses a superseded branch/source;
- it rebuilds accepted material only because a newer module/format exists;
- it treats external AI feedback as canon without disposition;
- it relies on a historical snapshot embedded in this router;
- it silently switches projects/books;
- it silently reopens locked story because production/audio tooling changed.

Re-route to the highest unblocked next obligation.

## CROSS-CONVERSATION LAW

A new conversation must not ask the Founder to repeat persisted state when it can be recovered.

Sibling/previous chat history is a discovery aid only. If it indicates that another conversation advanced the work, locate and verify the persisted artifact/state before treating the claim as production truth.

When Founder says `и / дальше / продолжай / делай / работай`:

1. run freshness sweep;
2. run stale-work gate;
3. restore exact active frontier;
4. execute highest unblocked obligation;
5. persist/version result;
6. verify;
7. update state pointer;
8. report `DONE / STATUS / EXACT NEXT ACTION`.

Do not restart planning, switch to an older branch, use a superseded draft or rely only on memory.
