# IVDIVO AUDIO — LIVE PROVIDER CANARY + CASTING CASCADE v1.0

**Status:** CURRENT UNIVERSAL COST-CONTROL / EVIDENCE GATE  
**Established:** 2026-08-21  
**Derived mechanism:** generalized from the successful ROOM 917 S0–S4 execution design; project-specific voices/lines are never transferred.

## PURPOSE

Do not spend provider credits on full episodes, hundreds of takes or full-season rendering before the provider path and the cast can actually prove themselves.

The studio buys **information in stages**.

This protocol applies when:
- LIVE TTS/voice provider calls cost credits/money;
- recurring voices are not yet locked;
- alignment/output-format/provider behavior must be validated;
- pair/ensemble chemistry or differentiation matters.

It does not change story canon or protected text.

## CASCADE

`ZERO-COST PREFLIGHT -> S0 TECHNICAL CANARY -> S1 FAIR ANCHOR COMPARISON -> S2 SECONDARY DISCRIMINATION -> S3 SPECIAL / FORBIDDEN-MODE STRESS -> S4 PAIR / ENSEMBLE TEST -> PROVISIONAL VOICE LOCK -> HARD PILOT -> SCALED RENDER`

Every stage is fail-closed. A later paid stage runs only for survivors from the prior gate.

## ZERO-COST PREFLIGHT

Before any paid call verify:
- current source/version/hash;
- exact-text protection mode;
- provider endpoint/model/output contract;
- authentication is environmental, never stored in canon/GitHub/Drive;
- voice candidate IDs are real provider IDs, not placeholders;
- request compiler/dry-run passes;
- output paths/ledgers are writable;
- retry policy is bounded;
- planned sample lines cover the actual performance risks.

No provider request occurs during dry-run.

## S0 — TECHNICAL CANARY

Goal: prove the execution pipe, not the actor.

Default size: **3–7 very short renders total**, usually one representative job per principal technical domain.

Test only what could invalidate all later spending:
- authentication/provider access;
- voice lookup/preflight;
- selected model exists;
- output codec/sample rate;
- timestamp/alignment response when required;
- Unicode/punctuation/quotes/names;
- file writing + metadata sidecars;
- request/response provenance;
- basic intelligibility/artifact absence.

S0 may use temporary candidates. **S0 can never create a voice lock.**

PASS result: `PASS_TO_S1`.

Hard fail examples:
- wrong output format;
- unusable alignment;
- provider/model mismatch;
- repeated pronunciation/parser failure on ordinary locked text;
- missing provenance;
- pipeline writes incomplete/corrupt files.

## S1 — FAIR ANCHOR COMPARISON

Goal: compare candidate voices fairly.

For each priority role, render the **same locked anchor text** with A/B/C candidates under matched conditions.

Rules:
- same exact text;
- same model family/settings where comparison requires it;
- loudness matched for review;
- no music/reverb/scene mix;
- candidate identity anonymized where practical;
- natural/restrained take first;
- no candidate-specific rewrite.

Score story function, not prettiness.

Typical lead dimensions:
- character contradiction;
- natural speech;
- distinctiveness;
- professional/status credibility;
- emotional/private register;
- direction potential;
- intelligibility;
- long-form risk.

Only survivors advance.

## S2 — SECONDARY DISCRIMINATION

Goal: spend only where S1 cannot resolve a meaningful choice.

Render additional material for surviving candidates only.

Use lines that discriminate the actual uncertainty, e.g.:
- humor vs seriousness;
- public vs private register;
- fatigue/pressure;
- technical vocabulary;
- shame without melodrama;
- command without shouting;
- clue delivery without exposition;
- warmth without sentimentality.

Do not render more material merely because credits remain.

## S3 — SPECIAL / FORBIDDEN-MODE STRESS

Goal: prove that the candidate can approach a dangerous mode without falling into it.

Examples by project:
- vulnerability without helplessness;
- authority without cold monotone;
- antagonist credibility without villain coding;
- threat without horror/supernatural coding;
- media certainty without caricature;
- intimacy without breathy romance;
- technical explanation without lecturer voice.

Use the project's actual forbidden modes and performance laws.

A candidate that repeatedly falls into a forbidden mode is rejected even if attractive in isolation.

## S4 — PAIR / ENSEMBLE TEST

Goal: prove relationships and speaker differentiation.

Only survivor combinations are tested.

For romance-bearing pairs, do not default to romantic lines. Use material where:
- attention matters;
- power/boundary grammar matters;
- humor/interruptions matter;
- one chooses to trust/comply/resist;
- attraction must remain subtextual at the current relationship state.

For ensembles test:
- blind speaker differentiation;
- rhythm collision/contrast;
- interruption naturalness;
- status hierarchy;
- whether one voice acoustically erases another.

Voice beauty is subordinate to assembled scene performance.

## PROVISIONAL VOICE LOCK

Allowed only after:
- no hard fail;
- role threshold passes;
- direction-change pass;
- device intelligibility pass;
- pair/ensemble gate where relevant;
- pronunciation risk is bounded.

`PROVISIONAL_PILOT_LOCK` is not automatically `SEASON_LOCK`.

Season/long-form lock requires the project-defined fatigue test plus performed pilot evidence.

## HARD PILOT

Only after provisional voice lock.

Produce the smallest scene/sequence capable of testing the actual show promise:
- real dialogue assembly;
- relevant critical SFX/space;
- no unnecessary full-library asset spend;
- mono/phone/low-volume/device translation;
- clue/causality comprehension;
- relationship/performance function;
- human/manual review where required.

If the pilot fails, diagnose the earliest layer before buying more renders.

## SCALED RENDER LAW

Full episode/season take plans remain valid **downstream capacity plans**, but they are blocked until the cascade reaches the required lock/pilot gate.

A 400-take plan is not an instruction to buy 400 takes before the cast is proven.

Scale only after evidence.

## PROJECT EXECUTION STATE

Every provider-facing project should maintain a compact state record containing:
- current stage;
- LIVE render performed?;
- voice lock status;
- current authority/source hash;
- zero-cost preflight result;
- S0/S1/S2/S3/S4 result;
- next action + job count;
- prohibited actions until evidence;
- provider/secret policy.

This state file is the cross-conversation continuation anchor.

## HARD STOPS

Before real evidence, never fabricate:
- rendered audio;
- provider success;
- listener reaction;
- voice lock;
- pair chemistry result;
- pronunciation success;
- alignment quality.

Never store API keys/secrets in GitHub, Drive, JSON, prompts or canon.

## FINAL LAW

**MINIMIZE SPEND BEFORE INFORMATION. TEST THE PIPE, THEN THE VOICE, THEN THE RELATIONSHIP, THEN THE SCENE, THEN SCALE.**
