# SECOND-PROJECT REPLICATION PROTOCOL

Purpose: decide whether the ROOM917 post-render engineering mechanisms should be promoted from project pilot to IVDIVO audio-domain authority.

Use one independent locked audio project with immutable real master bytes, at least two acoustic spaces or one meaningful room-state change, at least one authored/protected quiet beat, explicit cue/action contracts and a real human listen after machine repair.

Run:
1. Persist master bytes + readback checksum.
2. Build semantic cue lineage from that project's own authority; no ROOM917 names/assets.
3. Bind accepted/live timing.
4. Run signal analyzer.
5. Classify intervals fail-closed.
6. Generate only evidence-authorized repair plans.
7. Render at least one bounded patch.
8. Positive regression must PASS.
9. Deliberate unauthorized-change fixture must FAIL.
10. Human listen must show no causal/story regression.
11. Measure false positives and manual override count.

Promotion:
- PROMOTE_DOMAIN only if project-independent schemas/modules work unchanged except configuration and project data.
- ACCEPT_WITH_MODIFICATION if code is portable but one contract needs generalization.
- HOLD if human evidence or second project is unavailable.
- REJECT universalization if the apparent mechanism depends on ROOM917-specific structure.

Do not promote project-specific assets, cue IDs, thresholds-as-dogma, Scene3 timing, or story facts.
