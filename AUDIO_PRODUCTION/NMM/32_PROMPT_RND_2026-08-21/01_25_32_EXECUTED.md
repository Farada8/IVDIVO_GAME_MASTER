# NMM — EXECUTED PROMPTS 25–32

## PROMPT 25 — Economics / Automation

**Промт**  
Примени universal LIVE provider canary/casting cascade к NMM.

**Выполнение**  
NMM должен пройти `ZERO-COST PREFLIGHT -> S0 TECH CANARY -> S1 FAIR ANCHOR -> S2 DISCRIMINATION -> S3 FORBIDDEN-MODE STRESS -> S4 PAIR -> PROVISIONAL LOCK -> HARD PILOT -> SCALE`. Это полностью совместимо с созданным voice audition manifest и текущим null voice map.

**Вывод**  
Самая дорогая ошибка — рендерить episode до доказательства pipe/voice/pair.

**Решение**  
Не расходовать кредиты на full E01 до S4+pilot. Каждый stage fail-closed.

**Статус:** `PASS_PROCESS / LIVE_NOT_STARTED`

## PROMPT 26 — Economics / Automation

**Промт**  
Оптимизируй количество audition jobs без оценки денег, которых мы не знаем.

**Выполнение**  
S0: 3–5 коротких jobs для technical domains. S1: одинаковые anchor lines только для Isla/Leo/Vivian и ограниченного числа кандидатов. S2/S3 — только survivors. S4 — только survivor pair combinations. Security/Commentator — минимальные tests.

**Вывод**  
Оптимизировать нужно information gain per render, а не количество generated takes.

**Решение**  
Каждый paid job обязан иметь hypothesis + elimination value. Рендер без decision-use = запрещён.

**Статус:** `PASS`

## PROMPT 27 — Economics / Automation

**Промт**  
Оцени selective-regeneration architecture как механизм экономии и качества.

**Выполнение**  
E01 уже разбит на render blocks и aliases; clue-critical/phone/broadcast domains изолированы. Provider docs рекомендуют <=~2000 chars для reliable TTD; project ceiling 1800 дополнительно уменьшает blast radius при failure. Accepted blocks/takes/assets не меняются при локальной ошибке.

**Вывод**  
Малые логические rerender boundaries уменьшают стоимость дефекта и regression scope, но чрезмерная фрагментация ухудшает conversational performance.

**Решение**  
Break only on meaningful domain/clue/selective-repair boundary; не дробить по каждой реплике.

**Статус:** `PASS`

## PROMPT 28 — Economics / Automation

**Промт**  
Определи automation boundary: что можно автоматизировать, а что должно остаться human/manual.

**Выполнение**  
Автоматизируем: authority/hash checks, exact-text compilation, request validation, provider preflight, alignment normalization, asset/take ledger, device/machine QC, selective regeneration routing. Human/manual остаются: voice taste/identity, pair chemistry, spoiler-neutrality perception, long-form fatigue, listener comprehension, medical/legal specialist holds, final mix taste.

**Вывод**  
90–95% automation может быть производственной целью после locks, но не доказанным текущим результатом и не заменяет human evidence.

**Решение**  
Система хранит `MANUAL_REVIEW_REQUIRED` там, где judgement не может быть честно автоматизирован.

**Статус:** `PASS`

## PROMPT 30 — Red Team / Roadmap

**Промт**  
Назови три крупнейших креативно-аудиальных риска hard pilot.

**Выполнение**  
1) Isla может стать монотонной/noir/AI-precise. 2) Isla↔Leo может не создать adult friction/chemistry без романтического смягчения. 3) Vivian/score/SFX могут непреднамеренно спойлерить culprit; плюс whistle может быть слишком похож или слишком карикатурно отличен.

**Вывод**  
Это не те риски, которые можно надёжно закрыть документацией.

**Решение**  
Каждый риск получает отдельный S1–S4 или blind/device test; не объединять их в один subjective `sounds good` verdict.

**Статус:** `PASS`

## PROMPT 31 — Red Team / Roadmap

**Промт**  
Определи минимальный hard pilot, который проверит реальное обещание шоу без full E01.

**Выполнение**  
Предлагается двухсекционный pilot: A) opening -> confession -> security-call temporal contradiction (`11:47` vs `12:04`) для narration/evidence/audio clarity; B) короткий live Isla↔Leo/Vivian status exchange + final whistle-comparison excerpt для chemistry, institutional counterforce и clue identity. Между секциями не требуется притворяться, что это законченный episode.

**Вывод**  
Один cold open не тестирует relationship; один pair scene не тестирует центральный acoustic mystery. Нужны два компактных samples.

**Решение**  
Hard pilot = two causal samples, assembled with real post/critical assets, затем device + blind review.

**Статус:** `PROPOSED_HARD_PILOT`

## PROMPT 32 — Red Team / Roadmap

**Промт**  
Синтезируй следующий production order и stop conditions.

**Выполнение**  
Порядок: persist current state -> fresh ElevenLabs voice discovery -> zero-cost preflight -> S0 technical canary -> S1/S2/S3 voices -> S4 pair/ensemble -> provisional locks -> parallel whistle/space assets -> hard pilot -> take/asset locks -> real alignment -> timeline -> mix -> machine/device QC -> blind human listen -> selective repair -> specialist holds -> release gate. Stop only at real authority ambiguity, live evidence need, human decision, FATAL/MAJOR, provider/tool failure or specialist hold.

**Вывод**  
Система достаточно спроектирована, чтобы перестать расширять общие спецификации и перейти к evidence-producing execution.

**Решение**  
После этого R&D цикла новый prompt stack должен быть oriented на real evidence and selective repair, а не на повторный generic audit.

**Статус:** `PASS`
