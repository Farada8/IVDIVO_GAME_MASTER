# WAVE8 — SELF-IMPROVEMENT SYNTHESIS + PATH TO AUDIO NOVEL ENGINE V1

## Core conclusion

The engine is no longer mainly missing production architecture. Its limiting problem is **evidence strength and transition safety** between external reality and internal production state.

Wave6 solved byte-touch authorization. Wave7 exposed the real provider/human frontier. Wave8 therefore hardens the boundary immediately before real spend and human lock:

`PREFLIGHT -> TYPED PROVIDER SNAPSHOT -> HUMAN REVIEW PROVENANCE -> CONTROLLED LIVE LINEAGE ESCROW -> TYPED PROOF -> STATE TRANSITION`

## What became materially stronger

1. Provider capability evidence is now intended to be scope-explicit and hash-stable. A targeted voice lookup cannot masquerade as full account inventory.
2. Human review can be durable and auditable without turning the machine into the artistic authority.
3. Paid provider evidence can survive process/chat restart as an exact lineage without forcing duplicate spend.
4. PASS labels now have explicit evidence classes. Code/CI cannot be silently upgraded into human/live/measured claims.
5. Existing Session Resilience, Controlled Dispatch, Studio Evidence and Post-Render contracts remain authorities for their layers instead of being duplicated.

## Self-Improvement finding

The recurring engineering error is not simply “missing validation.” It is **evidence-class collapse**:
- a file exists, therefore someone calls it PASS;
- provider accepted, therefore someone treats it as a take;
- machine test is green, therefore someone calls performance good;
- one project works, therefore someone promotes a universal law.

Wave8's candidate improvement is a bounded provenance bridge that preserves evidence class through every state transition.

### Candidate status

**PILOT_CODE / HOLD_REAL_EVIDENCE**.

Do not allocate a new central SI identifier solely because code exists. First integrate, test, use on real provider/human evidence, then reconcile with current SI-0009/SI-0010 and the central registry. If it remains a distinct recurring mechanism after real use, register it with fresh ID readback.

## Stop rule

No further universal engine module is justified merely because another prompt can be written. A new shared module requires one of:
- a real deterministic test failure;
- real provider/account failure not representable by current contracts;
- real human-review ambiguity not representable by current ledger;
- duplicate-spend/recovery failure;
- real alignment/mix/QC failure;
- measured economics/reliability failure;
- cross-project portability failure.

Otherwise execute evidence collection rather than architecture expansion.

## V1 decision law

`GO` is impossible from code alone.

At minimum V1 requires verified current source/CI, authenticated provider evidence, real accepted audio and alignment, human performance/listener evidence, measured economics, durable restart recovery and cross-project live portability. Even then machine status is **GO_FOR_FOUNDER_V1_DECISION**, not self-declared production authority.
