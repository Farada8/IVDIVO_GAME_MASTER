# PROVIDER EVIDENCE SELF-IMPROVEMENT PROTOCOL v1

## Route
`FRESH AUTHORITY -> UPSTREAM REAL EVENT -> DURABLE ARTIFACT -> CLASS-SPECIFIC VALIDATION -> LINEAGE CHECK -> INVENTORY/STATE DERIVATION -> REAL NEXT EXPERIMENT -> RESULT -> LEARNING REGISTRY`.

## Earliest-cause taxonomy
- `ACQUISITION`: upstream authenticated read failed or evidence absent;
- `DURABILITY`: artifact/write/readback/hash evidence failed;
- `LINEAGE`: wrong run/attempt/source/account/snapshot family;
- `CAPABILITY`: model/voice inventory incomplete or drifted;
- `CAST_DESIGN`: provisional role/model/voice binding structurally invalid;
- `PERFORMANCE`: real pronunciation/direction/pair/fatigue evidence fails;
- `SPEND_DISPATCH`: canonical pre-spend/idempotency/provider-dispatch gate fails;
- `POST_RENDER`: live audio/alignment/mix/QC failure;
- `HUMAN`: real listener evidence fails;
- `ECONOMICS`: measured cost/time evidence fails.

Repair the earliest proven layer and invalidate only dependent descendants. A failure in one layer must not trigger unrelated story rewrite, full rerender, new provider adapter, or new top-level engine.

## Learning rule
A deterministic fixture may prove mechanics only. One real provider run proves only that exact provider/run lineage. A reusable improvement candidate requires evidence-family independence, regression proof and—where the claim is cross-project—independent project replication. Machine evidence cannot promote Human Signal or Founder authority.

## Stop law
When real provider evidence is available, consume it before expanding meta architecture. When it is unavailable, only bounded work that reduces the next real experiment's failure surface is admissible. Do not recursively execute future prompt banks merely to increase prompt count.
