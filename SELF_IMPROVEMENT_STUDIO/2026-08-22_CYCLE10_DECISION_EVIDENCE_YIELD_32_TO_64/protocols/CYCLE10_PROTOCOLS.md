# CYCLE10 PROTOCOLS — DECISION / EVIDENCE YIELD GOVERNANCE

## C10-P01 — Freshness before meta-write
Read current main, controlling Self-Improvement authority, registry family, and active registry-changing PR/branch reservations before any candidate ID or global write.

## C10-P02 — Decision/Evidence Yield
Every meta-action must name: decision changed, uncertainty reduced, existing mechanism checked, smallest decisive test, evidence class, and production obligation resumed.

## C10-P03 — Registry Reservation
`main registry complete != reservation view complete`. New global SI ID is forbidden without committed family + open reservation scan or transactional reservation proof.

## C10-P04 — Promotion Tribunal
Test count, prompt count, model agreement, persistence and package hashes cannot independently promote. Require application target, evidence families, replication diversity, regressions, rollback/readback, and all external gates actually satisfied.

## C10-P05 — Replication Diversity
Multiple cycles/reports on one project/root evidence family count once for independent replication. Cross-project evidence must instantiate the same mechanism with a healthy/negative control.

## C10-P06 — Pruning / Obsolescence
Candidate with no decision delta, duplicate mechanism, expired trigger, or overhead greater than avoided rework is MERGE / PRUNE / HOLD, not preserved by default.

## C10-P07 — Self-reference / rollback
Changes to Self-Improvement are bounded candidates. Preserve v2 VERIFIED_CURRENT; every application has protected authorities and rollback witness.

## C10-P08 — Library privacy / provenance
Private or unpublished raw sources remain Drive-only. GitHub stores pointer/hash/provenance unless explicit public-source authority permits raw publication.
