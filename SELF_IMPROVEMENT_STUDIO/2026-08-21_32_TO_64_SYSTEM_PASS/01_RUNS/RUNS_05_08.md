## PROMPT 05 — CAUSAL ARCHITECTURE + CHAPTER/EPISODE MAP

**ROLE:** Story Architect / Continuity / Mystery / Relationship Weaver

**MISSION:** Построить полный causal map без filler, lore chapters и маркетинговых хвостов вместо истории.

**MANDATORY INPUTS:**
- approved Story Core
- Character Engine
- Relationship Authority
- mystery/clue ledger if applicable
- world/system constraints
- format target

**EXECUTION:**
1. Для каждой главы/эпизода/major scene определи WHO WANTS WHAT / WHY NOW / ACTION / RESISTANCE / TURN / PRICE / STATE DELTA / OPEN QUESTION / PAYOFF.
2. Сделай causal dependencies явными: что создаёт следующий эпизод и что изменится, если узел удалить.
3. Проведи линии clues, relationships, ordinary life, work/money/status и world-system consequence через одну архитектуру, а не отдельные вставки.
4. Зафиксируй midpoint reclassification, escalation ladder, darkest consequence, climax action/choice и completed resolution.
5. Series hook открывай после closure текущей истории.
6. Создай fingerprints/dependency hashes для selective repair.

**RED TEAM / PROHIBITIONS:**
- FATAL: missing causal climax/resolution.
- MAJOR: protagonist passivity, weak midpoint, repeated escalation, fake stakes, unresolved main conflict, clue unfairness.
- Cut any chapter whose removal changes nothing.

**REQUIRED OUTPUTS:**
- `CAUSAL_CHAPTER_MAP`
- `SCENE_DEPENDENCY_DAG`
- `CLUE/RELATIONSHIP/EMOTION WEAVE`
- `ARCHITECTURE_RED_TEAM`
- `SCENE_CONTRACT_QUEUE`

**PASS/FAIL GATE:** PASS если каждый major node причинно нужен, escalation растёт, climax решает главный конфликт, resolution завершён.

**AUTO-CONTINUE:** Prompt 06 for prose execution.

## PROMPT 06 — SCENE / DIALOGUE / VOICE EXECUTION SYSTEM

**ROLE:** Prose Writer + Scene Director + Dialogue Editor + Voice Editor

**MISSION:** Написать следующий bounded block настоящей прозы, удерживая causal map и индивидуальные голоса.

**MANDATORY INPUTS:**
- current scene contracts
- character/relationship state entering scene
- P51 voice sheets
- P52 emotional targets
- P53 authority where applicable
- continuity knowledge state

**EXECUTION:**
1. На сцену: WHO WANTS WHAT / WHY NOW / WHAT STOPS / WHAT CHANGES.
2. Enter late, exit after state change. Object→Action→Implication вместо abstract explanation.
3. Dialogue as action: objective, resistance, asymmetry, interruption, subtext, withheld info, status move, changed decision/relationship.
4. Сохраняй ordinary life, work/money, embarrassment/humor/social danger, если они принадлежат книге.
5. После scene draft обнови state delta и knowledge state.
6. Run P51 shared-construction/voice collision; P52 observed emotional range; P53 only if relationship authority permits.
7. Если causal map стабилен — продолжай следующий scene. Если сломан — не импровизируй новый plot, эскалируй upstream.

**RED TEAM / PROHIBITIONS:**
- Generated-text patterns: repeated syntax, tiny paragraph rhythm, perfect thematic speeches, equal-airtime groups, moral explanation after action.
- No character made stupid for chemistry.
- No exposition disguised as dialogue.

**REQUIRED OUTPUTS:**
- `ACTUAL_PROSE_BLOCK`
- `SCENE_QA`
- `STATE_DELTA`
- `P51/P52/P53_LOCAL`
- `NEXT_SCENE_OR_UPSTREAM_DEFECT`

**PASS/FAIL GATE:** PASS если сцена меняет state, выполняет causal contract, voices distinct enough internally, continuity intact.

## PROMPT 07 — DEVELOPMENT + RED TEAM + TARGETED REPAIR

**ROLE:** Development Editor + Red Team + Repair Architect

**MISSION:** Найти реальную причину дефекта и починить минимальный слой, не переписывая всё произведение.

**MANDATORY INPUTS:**
- new manuscript block
- upstream Story Core/Architecture
- prior gates
- defect reports
- current repair capabilities

**EXECUTION:**
1. Классифицируй FATAL/MAJOR/MEDIUM/POLISH.
2. Для FATAL/MAJOR: symptom, exact evidence, root cause, earliest failed layer, smallest repair, protected invariants, acceptance test, descendants to rerun.
3. Если defect local — targeted patch. Если upstream — global/stage repair. Если wrong engine — Prompt 03.
4. Используй candidate-before-commit, QA, stale contract abort, no-effect rejection, transaction snapshot/rollback где возможно.
5. После commit rerun only true descendants and verify original defect no longer persists semantically.

**RED TEAM / PROHIBITIONS:**
- Не разрешать defect laundering: переименование проблемы ≠ fix.
- Не принимать reviewer fix только потому, что diagnosis верен.
- Не чинить story line edit'ом, audio problem текстом, relationship authority chemistry.

**REQUIRED OUTPUTS:**
- `RED_TEAM_REPORT`
- `REPAIR_CONTRACT`
- `CANDIDATE_DIFF`
- `REGRESSION_REPORT`
- `DEFECT_DISPOSITION`

**PASS/FAIL GATE:** PASS если FATAL=0 и accepted MAJOR устранены; оставшиеся medium/polish не маскируют upstream issue.
