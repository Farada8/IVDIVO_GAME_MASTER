# CYCLE9 SYNTHESIS — PATH TO A BETTER SELF-IMPROVING SYSTEM

## 1. What changed
Earlier cycles correctly solved much of capture, authority routing, durable persistence, recovery, evidence firewalls and bounded story-adapter pilots. The remaining systemic problem is now **calibration**: deciding which improvements are real, portable and worth keeping, while measuring their cost and avoiding duplicate meta-infrastructure.

## 2. Main defect classes observed across parallel work
1. **STALE_WHILE_CORRECT** — a branch/state can be valid at creation and obsolete before integration.
2. **EVIDENCE_LAUNDERING** — model/test/public evidence can be mislabeled as Human/provider/buyer proof.
3. **EVIDENCE_INFLATION** — many summaries/models from one raw root look like independent evidence.
4. **PROMOTION_INFLATION** — high test counts/green CI can be mistaken for CURRENT authority.
5. **NEGATIVE_EVIDENCE_LOSS** — failed transfer/counterexample can disappear behind a newer attractive mechanism.
6. **ENGINE_PROLIFERATION** — recurring ideas can generate duplicate allocators/transaction runtimes/routers.
7. **META_STARVATION** — improving the factory can consume time that should produce books/audio/real evidence.
8. **PROMPT_COUNT_GOODHART** — 32/64 generation can become ritual activity rather than uncertainty reduction.

## 3. New target architecture
`OBSERVATION -> EVIDENCE ROOT -> AUTHORITY SNAPSHOT -> CANDIDATE/DEFECT -> SEMANTIC DEDUPE -> OWNER/SCOPE -> CHEAPEST DECISIVE CANARY -> RAW RESULT -> NEGATIVE/POSITIVE RETENTION -> DECISION DELTA -> PROMOTION ELIGIBILITY -> EXPLICIT REVIEW -> APPLY/READBACK -> TELEMETRY -> PRUNE/RETURN TO PRODUCT`.

Durable writes and freshness are reused from existing owners. Cycle9 adds bounded visibility/control around them.

## 4. Promotion philosophy
Promotion is no longer treated as a scalar confidence threshold. It is a vector of non-substitutable obligations:
- authority/provenance known;
- development contract;
- pilot evidence;
- healthy/negative controls where relevant;
- adversarial review;
- regression;
- independent replication if scope claims portability;
- Human/provider/market evidence only when the claim requires that class;
- evaluation matrix;
- explicit scope;
- application map;
- rollback/readback plan.

Machine output: `ELIGIBLE_FOR_REVIEW`, never automatic `VERIFIED_CURRENT`.

## 5. Negative evidence as an asset
Cycle9 formalizes an important cross-project lesson: REDISCOVERY, COUNTEREXAMPLE, FAILED_TRANSFER, HOLD and PROTECT_NO_CHANGE can be high-value results. A system that only learns from positive PASS is structurally biased toward mechanism accumulation and Goodhart.

## 6. Observability objective
The useful future metrics are not number of prompts, documents, PRs or tests. Measure, when real data exists:
- decision route changed?;
- real defect prevented/caught?;
- false positive / false negative?;
- unnecessary rebuild avoided?;
- operator minutes changed?;
- rebase/write failure recovered?;
- product/evidence frontier advanced?;
- maintenance overhead created?;
- mechanism later pruned/narrowed?

Unknown measured values remain null.

## 7. Path to goal
### Stage A — Reliability
Keep authority/freshness/transaction/evidence firewalls fail-closed and single-owner.

### Stage B — Calibration
Apply promotion/negative-evidence/replication controls to existing candidates instead of inventing more.

### Stage C — Measurement
Capture real ImprovementEvents from normal production, not manufactured incidents.

### Stage D — Pruning
Narrow/retire helpers that show no decision delta or excessive false positives/maintenance cost after sufficient exposure.

### Stage E — Product return
The Self-Improvement engine should increasingly route work back to writing/audio/business/discovery whenever meta-work is not the current bottleneck.

## 8. Success condition
The system is improving when it:
- makes fewer unsupported claims;
- creates fewer duplicate engines;
- detects stale authority before destructive writes;
- preserves useful negative results;
- repairs smaller/earlier failure layers;
- leaves healthy assets untouched;
- promotes fewer but better-supported mechanisms;
- spends less meta effort per real decision improvement;
- returns faster to the actual product frontier.

## 9. Current decision
`CYCLE9 = BOUNDED_CANDIDATE_PACKAGE`.

No global v3 promotion. No new SI ID. No replacement of SI-0014/SI-0015 owners. Next evidence should come from real canaries, measured overhead and independent review rather than another generic architecture expansion.
