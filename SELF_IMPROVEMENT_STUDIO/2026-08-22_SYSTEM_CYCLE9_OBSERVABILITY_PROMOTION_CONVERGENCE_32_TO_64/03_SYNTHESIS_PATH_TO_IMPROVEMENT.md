## Strongest findings
1. **Freshness is real production evidence, not theory.** Main repeatedly advances during long work. A later main now contains the first genuine SI-0014 recovery event. Therefore stale state must be a typed write blocker.
2. **Negative evidence is an asset.** Discovery/Absolute-Math failures and healthy no-change controls prevent optimistic self-confirmation.
3. **Test count is not promotion evidence.** Deterministic tests prove machine behavior only. HUMAN, PROVIDER, FOUNDER, BUYER and PAYMENT classes remain separate.
4. **Evidence-family independence matters.** Ten model summaries from one raw root do not equal ten replications.
5. **Self-improvement needs a budget.** Meta-work is useful only when it removes a production bottleneck, prevents recurring failure or Founder explicitly selects it.
6. **New engines are expensive liabilities.** Extend existing owners when possible; require unique recurring state/coordination need before engine review.
7. **Promotion must become an explicit packet.** Candidate scope, development contract, pilot, adversarial review, regression, independent evidence where required, application targets, rollback and readback must be visible in one review object.

## Path to a better system
### Stage A — Observability
Every material improvement event should expose: raw evidence root, authority snapshot, event type, earliest failure layer, decision delta, avoided failure, operator effort, outcome, and existing receipt links.

### Stage B — Calibration
Measure false positives, false negatives, blocked wrong writes, avoided stale overwrites, genuine recovery success, operator/tool overhead and manual override rate. Avoid invented precision.

### Stage C — Promotion discipline
Use `ELIGIBLE_FOR_REVIEW`, never auto-promotion. Require evidence classes appropriate to the claimed scope. Universal claims need stronger cross-project/cross-domain independence than project-local claims.

### Stage D — Pruning
Retire helpers that are duplicate, unused, too costly, too noisy or fully absorbed by stronger current owners. Preserve provenance and negative results.

### Stage E — Return to product
When a higher-priority book/audio/product task is admissible and this meta-work is not its prerequisite, stop meta expansion and hand control back.

## Acceptance boundary
Cycle9 can be accepted as an **engineering candidate package** if its deterministic guards pass and GitHub/Drive persistence/readback is correct. Global Self-Improvement promotion remains a separate decision and is NOT implied by package completion.
