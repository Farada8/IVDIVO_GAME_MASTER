# CYCLE 3 — SYNTHESIS + PATH TO GOAL

## Target
Build an IVDIVO factory that produces **stronger completed books first, high-quality book-to-audio products second, and continuously improves its own execution without requiring the Founder to manually shuttle context, repeat `и`, or debug stale state**.

## What Cycle 3 actually proved

### 1. The bottleneck is no longer prompt count
IVDIVO already has enough prompts and specialist lenses. The recurring loss is between them: stale CURRENT surfaces, project-state normalization, authority scope, source identity, tool mutation, evidence promotion and write-through.

**Decision:** improve the execution spine, not another top-level creative OS.

### 2. Heterogeneous state can be normalized without flattening authority
Real pilots on BLOODBOUND, ROOM917, engine/package state and research state preserved different gate semantics. A generic adapter must normalize routing fields while preserving project-specific authority and blockers.

**Decision:** State Adapter remains a compatibility layer, never canon.

### 3. Shared facts must be upstream objects
D04 demonstrated that one exact clue line and one sound contrast have multiple downstream consumers. Independently rewriting them creates semantic/audio drift.

**Decision:** bind protected facts once; consumers reference them.

### 4. Story structure tools are diagnostics, not judges
BLOODBOUND's real causal grid supports graph extraction and selective descendant invalidation. But a graph signal cannot replace a human/story gate.

**Decision:** machine tools locate likely structural defects; dramaturgy decides meaning.

### 5. Book→audio compilation is strongest when source identity is cryptographic
NMM E01 already carries source-export and occurrence-ledger SHA-256 values. Exact text, occurrence coverage, processing-domain boundaries and voice-lock state can therefore be compiled deterministically without pretending that dry-run proves performance.

**Decision:** audio factories should consume hash-bound locked/current text authority.

### 6. Prompt IR is useful, but only as an execution contract
The real C3-18 task could be reduced to authority refs + delta + inputs + forbidden changes + outputs + gate + evidence. This removes repeated boilerplate. However no claim is made that a shorter packet always produces equivalent model output.

**Decision:** migrate gradually under equivalence canaries.

### 7. Transaction guards are now supported by live evidence
Two real GitHub stale-SHA attempts were rejected with HTTP409. A deliberately partial transaction was detected and marked `REPAIR_REQUIRED` rather than silently succeeding.

**Decision:** expected hash + readback + explicit partial-transaction state should become mandatory for mutable shared state.

### 8. Multi-AI value comes from disagreement + disposition, not voting
A real persisted Claude analysis contained several useful mechanisms and several ROOM917-specific recommendations that became stale. Reconciliation preserved the mechanisms while refusing stale project patch instructions.

**Decision:** same-source parity, independent reports, evidence-family clustering, explicit disposition, current-authority rebase.

### 9. Registry identity is a serious integrity surface
Cycle 3 found two unrelated `SI-0008` candidates. This was a MAJOR operational integrity defect. It was repaired by retaining transcript recovery as SI-0008 and migrating Meta-Orchestrator to SI-0012.

**Decision:** sharded unique-ID registry + deterministic compaction is safer than manual monolithic JSON surgery.

### 10. Package identity must remain immutable
Engine v11.2 remains the exact package that passed 290/290. New verified/piloted main extensions are not magically inside that ZIP.

**Decision:** selected modules enter only a new version after build, cold unpack, full regression and checksum.

### 11. Evidence class must cap claim scope
Cycle 3 explicitly rejected five common inflations: engineering tests→literary quality; dry-run→voice quality; audio metrics→acting/music/sellability; Story Gate→Founder Lock; model analysis→Human Signal.

**Decision:** every important PASS must say what evidence supports it and what it cannot prove.

### 12. Meta-work has reached a stopping threshold
More orchestration prompts now have lower expected value than real P1/P2 work. Founder authorized this bounded cycle, so it was correct to complete it; launching another 64-prompt execution ritual immediately would violate the engine's own starvation guard.

### Evidence acquisition
The largest unresolved information gaps are now outside internal reasoning:
1. actual reader/listener response;

## Operating law after this cycle
`PRODUCTION -> OBSERVE -> ROOT CAUSE -> SMALLEST PILOT -> EVIDENCE -> APPLY -> VERIFY -> LEARN`.

Do **not** use:
`MORE PROMPTS -> MORE PROMPTS -> MORE PROMPTS` as a proxy for improvement.

The 64 Cycle-4 prompts are therefore a **targeted future bank**. They are not permission to execute all 64 before returning to books/audio.
