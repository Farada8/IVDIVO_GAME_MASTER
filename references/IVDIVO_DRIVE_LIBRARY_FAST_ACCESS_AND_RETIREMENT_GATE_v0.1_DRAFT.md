## 5. Current deletion / retirement rule

### NOT YET SAFE TO MASS-DELETE THE ENTIRE CHATGPT FILE LIBRARY.

Reason:

1. Raw files are materially mirrored and organized on Google Drive.
2. The Drive connector can directly fetch full readable text from at least verified PDFs.
3. The audit/index layer exists.
4. BUT the current audit records filenames/metadata rather than a complete exact `Drive file ID / canonical folder / duplicate-retention` locator for every source.
5. Therefore deletion must be source-by-source or batch-by-batch only after the exact Drive locator is verified and entered here (or in the future CSV master).

### Retirement gate for one source

A ChatGPT/File-Library source can be retired only when:

`IDENTITY VERIFIED`
→ `DRIVE COPY FOUND`
→ `DRIVE FILE ID SAVED`
→ `FULL-TEXT FETCH TESTED OR RAW DOWNLOAD VERIFIED`
→ `COMPLETENESS STATUS SAVED`
→ `DUPLICATE GROUP RESOLVED`
→ `SOURCE CARD / PASSPORT LINKED IF STUDIED`
→ `SAFE_TO_RETIRE_FROM_CHATGPT = YES`.

If any stage is missing: **KEEP IN CHATGPT FILE LIBRARY FOR NOW**.

## 7. Retrieval rule after ChatGPT File Library deletion

When a source is marked `SAFE_TO_RETIRE_FROM_CHATGPT = YES`:

1. consult locator master;
2. open exact Drive file ID/URL;
3. retrieve relevant source text;
4. use existing source card/mechanism index first for routine drafting;
5. return to full source only for targeted verification, gaps, conflict between schools, exact examples/claims, or regression;
6. never claim a source was studied if lifecycle status does not support that label.
