**Version:** 1.0

**Status:** CANON / UNIVERSAL PRODUCTION STANDARD  
**Scope:** ALL CURRENT AND FUTURE IVDIVO AUDIO DEVELOPMENTS  

## Purpose

This document is the universal audio-production operating system for all IVDIVO projects: novels adapted to audio, narrated fiction, narrator-led multi-voice serials, full audio dramas, romantic mystery/dorama projects, pilots, trailers and future audio-first developments.

It governs **HOW an approved story is turned into audio**. It does **not** replace project-specific story canon, character bibles, episode scripts, production authorities or Founder decisions.

**PRIMARY LAW**  
STORY FIRST.  
CHARACTER SECOND.  
COMPREHENSION THIRD.  
SOUND SERVES STORY.  
MUSIC NEVER REPLACES DRAMA.

## 4. Delivery contract

Before audio production, identify the approved delivery mode:

**A. NARRATED FICTION** — novel-like single narrator, with dialogue performed inside narration.  
**B. NARRATOR-LED MULTI-VOICE** — narrator + principal character voices + selective SFX/music.  
**C. FULL AUDIO DRAMA** — scene-based multi-cast production with sound design.

Never accidentally mix delivery logic. If a platform requires another submission format, adapt presentation without changing approved causality, character, clue order or relationship state.

If delivery mode is not locked, mark `WORKING` and create the smallest pilot needed to compare formats. Do not silently choose a permanent format.

## 5. Story lock / feature freeze

Once the project story is locked, audio production cannot casually rewrite it.

Text changes are allowed only when:
- actor/TTS playback reveals a concrete spoken failure;
- multiple listeners reveal the same comprehension failure;
- a factual/continuity error is proven;
- pronunciation or wording creates a material audio ambiguity;
- a platform constraint makes the current line literally unperformable.

Repair the smallest responsible layer first:

`AUDIO DEFECT → audio`  
`PERFORMANCE DEFECT → performance`  
`EDIT/RHYTHM DEFECT → edit`  
`MIX DEFECT → mix`  
Only then consider wording.

After FEATURE FREEZE, do not add new conspiracies, relatives, mystery engines, romance triangles, lore or “cool” subplots unless needed to repair a FATAL defect.

## 7. Voice master law

**VOICE > TAGS.**

Reject a voice if it requires constant prompting/tags to resemble the character. Never select a voice from one attractive line.

Every major recurring voice should be tested in enough states to prove identity:
- neutral/ordinary;
- work/competence;
- humor;
- authority/status;
- pressure;
- vulnerability;
- high-stakes clue/reveal when relevant.

Voice Bible fields:
- character;
- age impression;
- accent/register if relevant;
- default energy 1–10;
- default tempo;
- sentence rhythm;
- vocabulary feel;
- humor behavior;
- stress behavior;
- vulnerability behavior;
- authority behavior;
- intimacy boundary;
- what the actor/TTS must NEVER play;
- pronunciation notes;
- approved voice/model/settings ID when locked.

A voice becomes AUDIO CANON only after it passes ordinary and pressure material.

## 8. Actor direction law

Dialogue is action. Do not direct actors with vague literary abstractions when a playable verb is possible.

For every important scene/block identify internally:
`CHARACTER / IMMEDIATE WANT / WHY NOW / RESISTANCE / STATUS BEFORE / TACTIC / SUBTEXT / SAID / UNSAID / UNSAYABLE / EMOTIONAL FLOOR / ENERGY / TEMPO / BREATH-PAUSE / TACTIC CHANGE / STATUS AFTER / WHAT MUST NOT BE PLAYED`.

Translate direction into playable actions such as: convince, contain, test, deflect, hide, provoke, protect, document, corner, reassure, dismiss, ask for help, recover control, refuse, bargain, confess, withhold.

Performance must express character truth, not genre cliché.

## 9. TTS / ElevenLabs method

Where ElevenLabs is used:
- use a current suitable model such as Eleven v3 when supported and appropriate;
- start from the most natural/balanced baseline before extreme expressiveness;
- use audio/performance tags sparingly;
- tags are production guidance, not canon;
- do not stack tags on every line;
- preserve pronunciation and character identity across episodes;
- generate **CLEAN DIALOGUE FIRST**.

Do not bake key ambience, evidence SFX, music or heavy phone/archive processing into core voice masters when separate tracks are practical.

For long-form work, do not generate an entire 10–15 minute episode as one uncontrolled take. Preferred render blocks: roughly 30–80 seconds, with enough surrounding context to preserve emotional continuity.

Regenerate only failed blocks. Lock good blocks. Do not waste credits chasing microscopic differences after a take already passes story/performance/comprehension.

## 10. Block lock gate

A dialogue block locks only when:
- words are exact;
- intention is correct;
- speaker is identifiable;
- clue/action is intelligible;
- emotional state is correct;
- pronunciation is correct;
- no accidental new implication appears;
- no canon change appears;
- no false romance/guilt/villain signal appears;
- rhythm is performable.

For critical lines, create at most:
- `TAKE A` — closest correction;
- `TAKE B` — controlled alternative;
- `TAKE C` — only when a truly critical clue/emotional beat warrants it.

Diagnose first: `VOICE MISMATCH / WRONG INTENTION / TOO THEATRICAL / TOO FLAT / WRONG TEMPO / WRONG STATUS / FALSE ROMANCE / FALSE GUILT / MISPRONUNCIATION / BAD PAUSE / UNCLEAR CLUE / TTS ARTIFACT`.

## 11. Sound-as-story law

Every important sound must have a story function.

Sound may communicate: `ACTION / PLACE / MATERIAL / DISTANCE / MEMORY / EVIDENCE / STATUS / RELATIONSHIP / CAUSAL CHANGE`.

Do not create decorative evidence. Do not add unexplained footsteps, whispers, knocks, voices, machines or glitches merely for atmosphere if a listener could read them as plot information.

A recurring clue sound must be recognisable, reproducible, distinct from similar sounds, causally consistent and mono-readable when plot-critical.

Once approved, a recurring motif becomes an AUDIO CANON ASSET and should not be regenerated into a different identity every episode.

## 12. Project sound identity

Each project must define its own audio palette rather than borrowing ROOM 917 or another project’s style.

Required project overlay:
- 3–8 signature recurring sounds, only if story-earned;
- room-tone library;
- evidence/technology sounds;
- environmental identity;
- music identity;
- negative sound prompt;
- sounds that must remain distinguishable;
- sounds that must never imply ontology/guilt/romance prematurely.

ROOM 917-specific motifs remain ROOM 917 canon only. They are not universal IVDIVO motifs.

## 13. SFX generation standard

For every required SFX define:
`ASSET ID / STORY FUNCTION / PHYSICAL SOURCE / MATERIAL / DISTANCE / SPACE / DURATION / ONE-SHOT-LOOP / FOREGROUND-BACKGROUND / CLUE-NON-CLUE / MUST BE DISTINCT FROM / GENERATION PROMPT / NEGATIVE PROMPT / MIX PRIORITY / BLIND-TEST QUESTION`.

For evidence-critical sounds, generate/select multiple candidates when useful and choose for:
**COMPREHENSION / PHYSICAL BELIEVABILITY / MEMORABILITY / NON-CLICHÉ**, not maximum drama.

---

## 14. Ambience / Foley law

Ambience establishes `PLACE / SIZE / MATERIAL / TIME / WEATHER / ACTIVITY / DISTANCE`. It must not invent plot.

Foley exists to embody action, orientation and causality, not to fill silence.

Build reusable project room tones when practical. Locations should sound materially different enough that a listener can orient without visual help.

---

## 15. Music law

Before adding music ask:
- What value has ALREADY changed?
- Why does this moment need music instead of silence?
- Will music obscure dialogue or clues?
- Is music implying romance, guilt, fear or importance before the scene earns it?
- Can the moment work without music?

If yes, prefer silence.

Music is strongest as `BUTTON / TRANSITION / AFTERMATH` or selective thematic return.

Avoid continuous underscore in forensic, investigative, documentary or proof-heavy passages unless the project’s approved style specifically earns it and comprehension remains clear.

---

## 16. Mix hierarchy

Universal priority:
1. SPOKEN CLUE / HUMAN ACTION
2. EVIDENCE SOUND REQUIRED FOR CAUSALITY
3. ROOM ORIENTATION
4. EMOTIONAL SILENCE
5. MUSIC

Music loses every conflict with comprehension.

Dialogue is the reference layer. Numerical dB offsets are starting guides only; final decisions come from listening across target devices.

Never make a critical clue understandable only through stereo placement.

---

## 17. Mobile / mono / speed law

Every release candidate should survive the relevant subset of:
`HEADPHONES / EARBUDS / PHONE SPEAKER / MONO FOLDDOWN / LOW VOLUME / 1.25× PLAYBACK`.

If a clue disappears on phone speaker, repair mix/processing before rewriting story.

## 18. Master production pipeline

Use this dependency order unless a project-specific authority states a stronger reason to change it:

`AUTHORITY RESTORE → DELIVERY CONTRACT → PROJECT AUDIO OVERLAY → CASTING BRIEF → INDIVIDUAL AUDITIONS → PAIR/CHEMISTRY/MEDIA-CONSISTENCY TESTS → VOICE LOCK → PRONUNCIATION LOCK → DRY DIALOGUE RENDER → ACTOR/DIALOGUE EDIT → DIALOGUE-ONLY QC → ROOM TONES → FOLEY → RECURRING WORLD SFX → STORY-CRITICAL EVIDENCE SFX → DEVICE/ARCHIVE/PHONE PROCESSING → MUSIC → MIX → QC EXPORTS → BLIND LISTENER TEST → DEFECT REGISTER → SURGICAL REPAIR → FINAL QC → MASTER LOCK → RELEASE EXPORT`.

Do not use expensive sound design to hide weak acting or unclear dialogue. Do not use rewritten dialogue to hide a mix defect.

---

## 19. Pilot-first rule

For a new audio production or a new delivery mode, validate the smallest high-value unit before rendering an entire season.

Recommended progression:
1. 30–90 sec voice/scene tests.
2. One pilot episode/chapter.
3. First 2–3 episodes when serial retention matters.
4. One dense late proof/climax scene if comprehension risk is high.
5. Only then scale production.

Existing completed scripts do not justify skipping audio validation.

## 20. Blind listener test

Do not simulate human test results.

Without notes/scripts, test whether target listeners can reconstruct:
- who the protagonist is;
- what they want now;
- why the scene/episode matters;
- key causal action;
- essential clue or change;
- current relationship state when relevant;
- what changed by the end;
- what exact question/next action they want next.

Record confusion/drop timestamps where possible.

`HOLD` when multiple independent listeners show the same material confusion or drop point. One loud tester is not a market. Real listener behavior outranks synthetic preference.

## 21. Audio Red Team

### FATAL
- decisive action cannot be understood without a screen;
- critical clue is masked or inaudible;
- sound creates a false canon fact;
- recurring evidence sounds that must differ are indistinguishable;
- character performance contradicts locked identity/ontology/relationship in a story-breaking way;
- wrong project branch is used.

### MAJOR
- speaker identity repeatedly unclear;
- protagonist sounds like genre caricature instead of character;
- antagonist/love interest is falsely coded guilty/romantic too early;
- technical/information scenes become homework;
- SFX wall masks dialogue;
- music tells the listener the answer/emotion before the scene earns it;
- TTS pronunciation repeatedly damages comprehension;
- location changes are confusing.

### MEDIUM
- comic/supporting voice becomes one-note;
- too many sounds compete;
- room identity is weak;
- recurring motif drifts;
- cliff or emotional beat is over-scored;
- pacing sags but causality remains clear.

### POLISH
- repetitive breaths;
- identical pauses;
- all voices share rhythm;
- over-clean TTS texture;
- minor edit/mic/processing artifacts.

## 22. Defect-to-repair controller

For every defect classify:
- `LAYER = voice selection / actor performance / pronunciation / text / edit / pause-rhythm / SFX / Foley / ambience / processing / music / mix / continuity / mastering / packaging`;
- `SEVERITY = FATAL / MAJOR / MEDIUM / POLISH`;
- earliest cause;
- downstream damage;
- protected working material;
- smallest high-leverage fix;
- retest required.

Fix dependency order, not the loudest symptom. Verify the defect in the repaired artifact; a note saying “fixed” is not proof.
