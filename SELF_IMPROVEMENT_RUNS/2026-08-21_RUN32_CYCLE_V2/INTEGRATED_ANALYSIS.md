## 1. What the 32 prompts actually proved

### MAJOR A — status convergence is not guaranteed
A file named CURRENT or DRAFT_STATUS can be stale relative to a later accepted terminal gate.
Concrete case: Book 2 DRAFT_STATUS still routes Pass C / Reader Advocate, while its Final Story Gate is GREEN / EXTERNAL-FEEDBACK READY and forbids another speculative broad rewrite.
Consequence: routing must compare authority strength + terminality, not filename alone and not timestamp alone.

### MAJOR B — machine documentation and executable resolver diverged
CURRENT_IVDIVO_ENGINE_MACHINE_EXECUTION still expresses blanket SAFE + ZERO_COST + REVERSIBLE continuation prerequisites.
The current resolver explicitly rejects those as universal prerequisites and uses real-gate semantics.
Consequence: a new dialog could follow the wrong machine pointer despite correct executable logic. Correct repair target is the pointer/contract, not regression of the resolver.

### MAJOR C — promoted package identity trails verified GitHub extensions
Self-improvement state explicitly records transcript recovery as a VERIFIED_CURRENT_POST_PACKAGE_EXTENSION with packaged_in_engine_v11_2_zip=false.
Consequence: current GitHub capabilities and the promoted v11.2 ZIP are not byte-equivalent capability sets. This is acceptable only if represented explicitly as post-package delta, not blurred into one “current engine” label.
