# IVDIVO / BODYGUARD — MULTILINGUAL CHARACTER VOICE ARCHITECTURE v1.0

**STATUS: SUPERSEDED BY `21_MULTILINGUAL_CHARACTER_VOICE_ARCHITECTURE_v2_0.md`**

Historical v1.0 retained for provenance. Do not use as CURRENT authority.

PRIMARY PILOT LANGUAGE: Russian
EXPANSION LANGUAGES: English, Spanish, German, Italian
PRINCIPLE: one character identity, potentially multiple language-native voice implementations.

# 1. CORE LAW
Do not cast five unrelated voices for one character.

Create a CHARACTER VOICE PASSPORT that remains stable across languages:
apparent age; pitch/range; vocal weight; texture; speaking tempo; breath behavior;
public/private register contrast; humor rhythm; stress behavior; vulnerability signature;
authority signature; intimacy boundary; forbidden modes.

Then create language editions:
CHARACTER_ID
├── RU
├── EN
├── ES
├── DE
└── IT

Each edition may use:
A. SAME VOICE ID — only if it passes native-language quality;
or
B. LANGUAGE-SPECIFIC SIBLING VOICE — if same ID creates accent, prosody, pronunciation, emotional or cultural mismatch.

Voice identity > voice-ID identity.

# 2. LANGUAGE PRIORITY
TIER 1 — RUSSIAN
Primary pilot / first casting and emotional calibration.

TIER 2 — ENGLISH
Build immediately after Russian pilot identity stabilizes.
BODYGUARD source script is English, so English is an independent performance master, not a mechanical translation of Russian timing.

TIER 3 — SPANISH
Next expansion language.
Select regional target before lock: Spain or LATAM/Mexico. Do not assume one Spanish accent serves every market.

TIER 4 — GERMAN / ITALIAN
Prepare architecture now, but do not pay for full-season casting/render before RU + EN evidence and business/distribution need.

# 3. SAME-VOICE VS SIBLING-VOICE GATE
Test the same Master Voice in each language first.

PASS SAME VOICE only if:
- pronunciation native/plausible;
- no source-language accent leakage;
- punctuation/rhythm natural;
- stress placement correct;
- emotional register survives;
- character age/status stays stable;
- P51 fingerprint survives;
- P53 vulnerability/chemistry survives;
- 8–10 minute fatigue test passes.

If any major failure:
CREATE LANGUAGE-SPECIFIC SIBLING VOICE.

Do not try to repair a strong accent with excessive prompting.

# 4. SIBLING VOICE MATCHING
A sibling voice does not need identical waveform/timbre.
It must preserve perceptual character invariants.

NAOMI:
grounded low-mezzo/alto impression; precise; economical; controlled authority;
dry humor; under personal pressure becomes quieter, not softer;
no maternal/seductive/action-hero coding.

ELI:
attractive natural medium/medium-low male voice; public polish vs private economy;
musician rhythm; vulnerability as rhythm/breath fracture;
no helplessness; no alpha possession.

Target:
“this is Naomi/Eli in another language,”
not:
“this is literally the same acoustic file speaking another language.”

# 6. LOCALIZATION LAW
Do not translate line-for-line mechanically.

Preserve:
1 story function
2 clue meaning
3 character objective/tactic
4 status/power
5 P51 voice
6 P52 temperature
7 P53 relationship function
8 timing burden
9 joke function
10 cultural naturalness

Exact words may change where literal translation sounds unnatural.

But clue facts, consent meaning, professional meaning, relationship stage and culprit/fair-play information cannot drift.

Each localized script becomes its own locked text authority after localization QA.

# 7. LANGUAGE-SPECIFIC P53
P53 must be rerun on localized dialogue.

Chemistry is carried by timing, register, pronouns, politeness, word order, interruption and subtext — all language-dependent.

Route:
TRANSLATE → NATIVE DIALOGUE PASS → P51 → P52 → P53 → AUDIO TEST.

# 9. COST CONTROL
Do not generate five full seasons in parallel.

Start with:
5 languages × 2 leads × short anchor test.

Per language:
S0 → S1 → survivors → pair → pilot.

Scale only languages that pass both:
QUALITY GATE + BUSINESS/DISTRIBUTION GATE.

# 10. DATABASE LAW
Character identity is canonical.
Language voice IDs are production implementations.

Never write:
NAOMI = voice_id XYZ

Write:
NAOMI_CHARACTER_VOICE_IDENTITY = VOICE_PASSPORT_NAOMI_v1
NAOMI_RU_IMPLEMENTATION = ...
NAOMI_EN_IMPLEMENTATION = ...
NAOMI_ES_IMPLEMENTATION = ...

This permits provider/model/voice replacement without changing character canon.

# 12. RELEASE RULE
A language edition is not release-ready because TTS is intelligible.

It must pass:
native-language listener QA; P51/P52/P53; clue/professional/consent equivalence;
pair chemistry; long-form fatigue; mono/mobile; blind audience test;
localization proof; rights/release QC.
