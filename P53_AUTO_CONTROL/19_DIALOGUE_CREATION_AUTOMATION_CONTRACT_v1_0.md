# IVDIVO — DIALOGUE CREATION AUTOMATION CONTRACT v1.0

**STATUS:** CURRENT EXECUTION CONTRACT

When the studio is asked to create dialogue, it must not jump straight to prose.

## INPUT RESTORE

Load only:
- active project/book/episode source of truth;
- current scene objective/turn;
- relationship/power state;
- P51 fingerprints;
- P52 temperature;
- relevant mystery/professional/continuity constraints;
- current P53 runtime.

## EXECUTE

1. Classify scene A–I.
2. Determine objectives, private desires, fear, status, withheld information and information asymmetry.
3. Verify scene desire/resistance/tactic/turn before line writing.
4. Draft one strongest dialogue version.
5. Run P51 voice-swap test.
6. Run P52 temperature/contrast test.
7. Run P53 if applicable.
8. Run professional truth / consent / clue timing / continuity.
9. Run anti-cliché / repeated-function scan.
10. Output one integrated dialogue.
11. Run Text Compliance on the produced text.
12. PASS → persist/use. REVISE → patch smallest failed function and re-audit. HOLD → stop at real gate.

## DO NOT

- generate five variants instead of choosing;
- add romance because both leads are present;
- make every scene high-temperature;
- replace subtext with explanation;
- make professional characters stupid for chemistry;
- use generic micro-beats as decoration;
- rewrite locked siblings not invalidated by the patch;
- claim human/market validation from internal scoring.

## LEARNING HOOK

If the same dialogue defect recurs across 2+ projects or repeated human/production evidence, create a learning-ledger entry and route a candidate system improvement through the Controlled Self-Improvement Engine.

## SUCCESS

Dialogue changes story/relationship/status and sounds character-specific while preserving the current story engine.
