## 1. Hard rule

Do not line-edit a scene until it has passed structural admission.

`SCENE CANDIDATE → FUNCTION + EXIT STATE → CAUSAL POSITION → UNIQUE VALUE → MODE/WEIGHT → KEEP/MERGE/SUMMARY/DELETE/REBUILD → PROSE REVISION`

If the scene should not remain a full scene, sentence polish is wasted work.

---

## 2. Scene admission card

For every questionable scene fill:

- **Owner / affected agent:**
- **Prior consequence:**
- **Primary function:**
- **Exact scene event:**
- **Exit state:**
- **Downstream dependency:**
- **Why exact real-time unfolding matters:**
- **Could enter later?** YES / NO
- **Could summarize?** YES / NO
- **Could merge with adjacent scene?** YES / NO
- **Recommended mode:** FULL / EMBEDDED / FRAGMENT / SUMMARY / COMMENTARY
- **Weight:** HEAVY / MEDIUM / LIGHT / COMPRESSED
- **Admission:** KEEP / MERGE / SUMMARY / DELETE / REBUILD

Line edit begins only after `Admission = KEEP` or after structural repair.

---

## 3. Function-duplication pass

Represent each nearby scene as:

`[FUNCTION] + [EXIT STATE]`.

If two nearby scenes have materially identical values, test merge/compression before prose work.

This is mandatory for:

- repeated technical tests;
- briefings/reviews;
- travel/logistics;
- repeated relationship reassurance/conflict;
- repeated evidence interpretation;
- worldbuilding demonstrations.

---

## 4. Action / response coupling

Do not force separate reaction sentences after every action.

Use:

`ACTION / NEW INFORMATION ↔ POV RESPONSE / MODEL / RELATION CHANGE`.

Coupling may occur at sentence, paragraph, scene or delayed-scene level.

If several beats form one perception or decision, prefer coherent paragraph movement.

---

## 5. ROOM 917

Protect real-time only when exact unfolding changes at least one of:

- clue provenance/status;
- Elena↔Julian trust or boundary;
- consent;
- investigative tactic;
- access/disclosure;
- decision ownership.

Routine recorder/contact-mic setup, repeat playback, travel and already-understood verification should normally be compressed unless a new function appears.

Hard firewall:

`RELATIONSHIP STATE ≠ EVIDENCE STATUS`.

A kiss, confession, attraction or trust does not corroborate a clue.

---

## 6. Orbital Youth

Before another training/technology scene, compare its function and exit state to the previous one.

Reject `TECH TOURISM`:

`NEW TECHNOLOGY ≠ NEW SCENE FUNCTION`.

Preferred causal pattern:

`WORLD RULE → PERSON-SPECIFIC AFFORDANCE/FRICTION → CHOICE → CONSEQUENCE`.

Post-money firewall remains: novelty, access and qualification cannot become disguised purchasing power.

---

## 7. B07 — THE UNLISTED CITY

Full scene priority:

`PATTERN → INDEPENDENT PERSONHOOD EVIDENCE → HUMAN CATEGORY BECOMES INADEQUATE → ENTITY PREFERENCE/REFUSAL → HUMAN OPTION SPACE CHANGES → BOUNDED ACCOUNTABLE DECISION`.

Human discussions that only restate `our category is inadequate` should merge/compress.

After personhood threshold, continuity choice remains with the nonhuman entity.

---

## 8. Conscious robots

A robot scene earns reader time through independent agency, not sensor novelty.

`OWN WANT → OWN MODEL/EVIDENCE → OWN RELATIONSHIPS → CONSENT/REFUSAL → CHOICE → CONSEQUENCE`.

No universal robot voice. No assumption that observed behavior reveals motive.

---

## 9. Consciousness-practice schools

A scene can change a practitioner's commitments without changing world ontology.

Maintain:

`OBSERVATION → REPRODUCIBLE EFFECT → SCHOOL INTERPRETATION → COMPETING INTERPRETATION → INDEPENDENT TEST → ONTOLOGY CEILING`.

Do not spend a full scene on terminology unless it changes practice, evidence, relationships or decision.

---

## 10. LESSON ZERO Book One

Development lock remains.

This gate may reopen a local scene only with concrete defect evidence such as:

- duplicate function/exit state;
- repeated logistics/process in real time;
- scene starts before consequential material;
- state-neutral scene;
- choppy action/reaction fragmentation caused by over-dramatization.

Standing production law:

`NO NEW EVIDENCE → NO NEW GLOBAL REWRITE`.

---

## 11. Anti-choppy revision order

`BOOK ENGINE → CHAPTER FUNCTION → SCENE ADMISSION → SCENE FUNCTION/EXIT STATE → SCENE WEIGHT/MODE → ORDER/DURATION/FREQUENCY → POV/EVIDENCE → ACTION-RESPONSE COUPLING → PARAGRAPH INTENT → READER-STATE CONTINUITY → SENTENCE RHYTHM → WORDING`.

Do not repair a structural problem with sentence-length manipulation.
