# IVDIVO — BATCH 167 APPLICATION GATE
## Green & Kremer — Process · Causality · Dialogue · Character-Relative Stakes

**Source status:** provisional application from a source still in FULL READ IN PROGRESS.

## 1. ONE MAIN STORY

Before adding a character, technology, relationship thread or complication:

`WHAT EXISTING CAUSAL ENGINE DOES THIS CHANGE?`

If the answer is only `adds colour / makes it more exciting / shows more world`, the material is a candidate for bank, compression or deletion.

## 2. Plan / text / canon separation

Maintain four separate states:

- **PLAN** — intended future structure;
- **ACTUAL TEXT** — what the manuscript currently establishes;
- **CANON** — approved world/character facts;
- **EVIDENCE STATUS** — what characters/readers can legitimately conclude in-story.

A production document does not become canon by repetition.

## 3. Character-relative stakes in post-money IVDIVO

Do not import the source's money/status examples literally.

Prefer non-fungible stakes:

- trust;
- consent;
- time of a specific person;
- privacy;
- concrete role / responsibility;
- unique access or mission slot;
- mastery;
- belonging;
- relationship terms;
- evidence integrity;
- safety.

## 4. Character differentiation

For every major character under the same event, record:

`WHAT THEY NOTICE → WHAT THEY WANT → WHAT THEY FEAR LOSING → EVIDENCE THRESHOLD → FIRST TACTIC → SECOND TACTIC IF BLOCKED`.

If five characters produce the same sequence with different slang, differentiation is cosmetic.

## 5. Supporting-person personhood

Even when a character performs a helper/hinderer/mentor/opponent function:

`OWN WANT → OWN MODEL/EVIDENCE → OWN RELATIONSHIPS → CONSENT/REFUSAL → CHOICE → CONSEQUENCE`.

For conscious robots/nonhumans this is mandatory.

## 6. Dialogue admission

Use direct dialogue when exact wording changes at least one of:

`TRUST / CONSENT / EVIDENCE ACCESS OR STATUS / AUTHORITY / RELATIONSHIP TERMS / DECISION / COMMITMENT / FUTURE OPTION SPACE`.

Otherwise test summary or indirect dialogue.

### Dialogue knowledge matrix

For important conversations track:

`SPEAKER KNOWS / LISTENER KNOWS / READER KNOWS / SPEAKER THINKS LISTENER KNOWS / DELIBERATELY WITHHELD`.

This is required for ROOM 917 and all mystery threads.

## 7. Mystery firewall

`UTTERANCE / PAUSE / GESTURE / SILENCE → POV HYPOTHESIS`, not corroborated fact.

Keep:

`WORLD FACT → TRACE/SOURCE → ACCESS → INTERPRETATION → ALTERNATIVE MODEL → CORROBORATION → STATUS UPDATE`.

For ROOM 917 specifically:

`TRUST / ATTRACTION / KISS / CONFESSION / SILENCE / INFLECTION ≠ CORROBORATION`.

## 8. Opening gate

Do not retrofit an opening merely because the source recommends a bang.

Use:

`ATTENTION + ORIENTATION + PERSON/SUBJECT BOND + STORY PROMISE + FORWARD PRESSURE`.

Valid modes include responsibility, relationship, mystery trace, competence, ordinary-life deviation, voice/attitude and action.

## 9. Conflict gate

Do not manufacture a villain when the true resistance is:

- insufficient evidence;
- two legitimate values;
- consent;
- embodiment;
- physical environment;
- institutional procedure;
- time;
- relationship history;
- incompatible objectives.

Use:

`WANT / RESPONSIBILITY → RESISTANCE / SUPPORT → TACTIC → OUTCOME → CHANGED STATE`.

## 10. Powerful-tool gate

Before allowing a technology/AI/authority to solve a problem:

`CAPABILITY → LIMIT → ACCESS CONDITION → COST → COUNTERFORCE → WHO MAY REFUSE`.

This prevents `sonic screwdriver` causality.

## 11. Anti-choppy / line-editing gate

Do not infer pace from white space.

`BOOK ENGINE → CHAPTER FUNCTION → SCENE ADMISSION → SCENE WEIGHT/MODE → POV/EVIDENCE → EXPOSITION/DIALOGUE OWNERSHIP → PARAGRAPH INTENT → READER-STATE CONTINUITY → SENTENCE RHYTHM → WORDING`.

If several microbeats belong to one perceptual/decision unit, test one coherent paragraph before adding more fragments.
