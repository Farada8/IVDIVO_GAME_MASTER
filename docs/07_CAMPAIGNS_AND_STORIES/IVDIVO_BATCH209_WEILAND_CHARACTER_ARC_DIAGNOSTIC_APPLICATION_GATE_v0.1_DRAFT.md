# IVDIVO BATCH 209 — CHARACTER ARC DIAGNOSTIC APPLICATION GATE

**Source:** K.M. Weiland — *Creating Character Arcs Workbook*  
**Status:** DRAFT / manuscript-facing production gate  
**Date:** 2026-08-22

## Purpose
Use character-arc theory to diagnose observable behavioural trajectories without importing a mandatory `Lie → Truth → healing` formula into IVDIVO.

## 1. Arc admission
Before allocating book-level space to an arc, answer:
1. What current model/value does the character use?
2. What does the character want or feel responsible for now?
3. What pressure/evidence/relationship makes the model costly or useful?
4. What tactic follows?
5. What state changes?
6. What later scene depends on this change?

Pass condition:
`ARC / STABILITY → CHANGES MAJOR CHOICE / RELATIONSHIP / EVIDENCE THRESHOLD → CHANGES ONE MAIN STORY`.

If no downstream dependency exists: compress, merge or bank.

## 2. Arc proof
Do not write “the character has changed.”

Use analogous pressure cases:
`EARLY CASE → RESPONSE A`  
`LATER CASE → RESPONSE B`.

Acceptable proof includes changed:
- tactic;
- evidence threshold;
- boundary/consent behaviour;
- trust/disclosure;
- authority use;
- responsibility;
- willingness to delegate;
- future option selection.

## 3. Tested stability
A character who keeps a core value may still have a full book trajectory.

`CORE VALUE → PRESSURE → COST / DOUBT → ADAPTIVE TACTIC → VALUE RETAINED / REFINED`.

Do not manufacture a conversion merely to satisfy a character-arc template.

## 4. Want / Need router
Use neutral production language.

`WANT = trackable present objective / desired outcome`.

`NEED = capability / knowledge / relationship condition / strategy that may permit better action`.

Firewall:
`NEED ≠ AUTHOR'S MORAL TRUTH`.

## 5. Ghost / trauma firewall
Before adding a wound/Ghost:
`IS CURRENT BEHAVIOUR ALREADY EXPLAINABLE THROUGH CULTURE / RELATIONSHIP HISTORY / INCENTIVE / EXPERIENCE / VALUE CONFLICT?`

If yes, no trauma is required.

Do not scale trauma upward merely because an arc is large.

## 6. Mystery / evidence
A character’s “Moment of Truth” may be only a model update.

`TRACE/SOURCE → ACCESS → INTERPRETATION → ALTERNATIVE MODEL → DISCRIMINATING TEST → STATUS UPDATE`.

Never permit:
`CHARACTER TRUTH → WORLD FACT`.

## 7. ONE MAIN STORY
In ensemble books:
`CHARACTER STRAND → UNIQUE LOCAL CHANGE → EFFECT ON ANOTHER STRAND / MAIN ENGINE → CONVERGENCE / PAYOFF`.

Do not give equal screen time merely because saga characters are equally important at franchise scale.

## 8. Relationship arcs
Do not use another person as cure/completion.

`TWO COMPLETE AGENTS → MUTUAL PRESSURE → TRUST / DESIRE / BOUNDARY / DISCLOSURE CHANGE → EXTERNAL CHOICE CHANGES`.

`LOVE / KISS / CONFESSION ≠ EVIDENCE`.

## 9. Nonhuman personhood
Never force a conscious robot/nonhuman into a human wound/healing template.

Required personhood fields:
`OWN PRIORITY → OWN MODEL/EVIDENCE → OWN RELATIONSHIPS → CONSENT/REFUSAL → CHOICE → CONSEQUENCE`.

`BECOMING MORE HUMAN ≠ CHARACTER DEVELOPMENT`.

## 10. YA / Orbital Youth
Preferred stakes remain non-fungible:
- autonomy;
- belonging;
- privacy;
- consent;
- mastery;
- first real responsibility;
- trust;
- reputation;
- unique mission/opportunity;
- relationships;
- time.

Do not re-import salary/rent/credits as the default engine.

Strong escalation remains:
`COMPETENT ACTION → REAL SUCCESS → MORE TRUST / ACCESS / RESPONSIBILITY → HARDER NEXT CHOICE`.

## 11. Theme
`QUESTION → COMPETING MODELS → ACTIONS → CONSEQUENCES → READER INFERENCE`.

Do not make narrator, mentor, school or institution deliver the official “Truth.”

## 12. Structural percentage firewall
Do not retrofit live manuscripts to 25/50/75/88/98% landmarks.

A structural turn is accepted because it materially changes objective, evidence, relationship, authority, responsibility, strategy or future option space.

## 13. LESSON ZERO Book One
Standing verdict: **KEEP DEVELOPMENT LOCK**.

No new reader/audio/canon/continuity defect has been established by this source.

`NO NEW EVIDENCE → NO NEW GLOBAL REWRITE`.

If future evidence identifies an arc problem, first run the Early/Later Analogous Pressure Test before changing book structure.

## 14. Prose / anti-choppiness
`ARC BEAT ≠ SENTENCE BREAK ≠ PARAGRAPH BREAK`.

Do not render every realization/reversal as:
`short sentence → one-line paragraph → explanatory short sentence`.

Repair order:
`SCENE FUNCTION → POV/EVIDENCE → CHARACTER TACTIC / TURN → PARAGRAPH INTENT → READER-STATE CONTINUITY → SENTENCE RHYTHM → WORDING`.

## Release condition
A character-arc repair passes only when:
1. actual behaviour under pressure changes or tested stability is proven;
2. downstream scene state changes;
3. ONE MAIN STORY becomes clearer, not more episodic;
4. evidence/personhood/consent boundaries remain intact;
5. prose rhythm is not degraded by template beats.
