## Mechanism 1 — Harvest consequences before inventing events
Bickham's §34 strongest durable principle is not simply “reuse things.” It is causal economy.

`EXISTING EVENT / PERSON / OBJECT → DIRECT CONSEQUENCE → SECONDARY CONSEQUENCE → RELATIONSHIP / EVIDENCE / ACCESS / RESPONSIBILITY CHANGE → LATER PAYOFF`

Before adding a new anomaly, attack, technology, secret, witness or side character, ask what the current material still owes.

### Gate B139-G01 — Consequence Harvest
For every major event, list at least three plausible downstream consequences in different domains before inventing a new event.

Possible domains:
- action / physical state;
- evidence / knowledge;
- relationship / trust;
- authority / access;
- responsibility / liability;
- public interpretation / reputation;
- future option space.

### Failure mode — NEW EVENT ADDICTION
A manuscript keeps producing new incidents because existing incidents are not allowed to propagate.

### Failure mode — ONE-USE EVENT
An event exists only to introduce a character, deliver one clue, or create one scene, then disappears from causal memory.

## Mechanism 2 — Role telescoping
Bickham proposes reusing one minor character for several small functions instead of proliferating a new doorman, driver, reporter, clerk and witness for every need.

Useful production test:

`ROLE A + ROLE B → SAME PERSON? → DOES CAUSALITY TIGHTEN? → DOES READER LOAD DROP? → DOES THE PERSON BECOME MORE INTERESTING?`

### Gate B139-G02 — Bit-Player Economy
When two walk-on/minor roles serve compatible functions and no independent personhood obligation requires separation, test combining them.

### Failure mode — BIT-PLAYER PROLIFERATION
The reader must track many names whose only purpose is one transaction each.

## Cross-source correction — function is not personhood
Bickham's economy principle must be limited by Card, Corbett, Herman, Crouch, Murderbot and the IVDIVO nonhuman-personhood system.

Do **not** combine two characters if the merge would erase:
- independent goals;
- meaningful relationship differences;
- consent/refusal;
- independent evidence provenance;
- a distinct affected party;
- decision ownership;
- embodiment-specific experience.

`BOOK FUNCTION ≠ STORYWORLD PERSONHOOD`.

### Failure mode — CHARACTER COMPRESSION ERASURE
A cleaner plot is purchased by deleting morally or causally necessary independent agency.

## Mechanism 3 — Consequence reuse strengthens ONE MAIN STORY
A strong single story engine does not mean “few events.” It means later events remember earlier ones.

`EARLY EVENT → STATE CHANGE → LATER CHOICE MADE DIFFERENT → PAYOFF`

This is stronger than superficial callback/repetition because the earlier event changes what is possible later.

### Gate B139-G03 — Causal Memory
If removing an earlier event leaves all later choices unchanged, test whether that event is ornamental, underpaid, or should be merged.

## Mechanism 4 — Revision completion is not line polish
Late §35 material confirms a multi-pass revision mentality: inspect chapter endings, total story logic/motivation, and whether the ending actually answers the problem/question created by the beginning.

Cross-source synthesis with Bell, LaPlante, Rosenfeld, Zinsser, Swain and Pushman yields:

`BOOK PROMISE / ENGINE → CAUSAL LOGIC → CHARACTER/RELATIONSHIPS → SCENE FUNCTION → POV/EVIDENCE → ENDING CONTRACT → PARAGRAPH/RHYTHM → WORDING`.

### Gate B139-G04 — Macro Before Finish
A manuscript is not “finished” because sentences are polished. Before final line edit, prove:
- dominant book question/promise is legible;
- major causal transitions work;
- character decisions have reasons and consequences;
- repeated scenes are not performing the same job;
- ending provides earned local closure.

### Failure mode — REVISION-AS-LINE-POLISH
The manuscript receives sentence-level polish while structural repetition, missing causal links or ending debt remain.

## Limits on Bickham's revision checklist
Bickham's late advice favors hooks, twists, disasters and unequivocal story-question answers. IVDIVO does not universalize those prescriptions.

A chapter ending needs a **read-on reason**, not necessarily a twist or disaster.
A book ending needs earned **local closure**, while a global saga mystery may remain bounded/unknown.

`LOCAL PROBLEM RESOLVED → COST / AFTERMATH → CHANGED STATE → OPTIONAL SAGA VECTOR`.

### Failure mode — CLIFFHANGER CHECKLIST
Every chapter is forced to end with an artificial twist/disaster.

### Failure mode — ENDING-QUESTION FLATTENING
A complex ethical/mystery ending is reduced to a binary answer even when the evidence only supports a bounded operational conclusion.

## IVDIVO applications
### Orbital Youth
Before adding another technology or system failure, propagate consequences of an existing decision through trust, qualification, authority, access, responsibility and relationships.

### B07 / nonhuman personhood
Do not reuse/merge witnesses or nonhuman entities if independent source lineage or consent is necessary to establish personhood and legitimacy.

### ROOM 917 / mystery
A clue should ideally pay more than once: immediate inference, later reinterpretation, relationship effect, procedural consequence, or payoff. But reuse must remain fair; do not retroactively invent properties that were not planted.

### LESSON ZERO Book One
No development-lock override. Use consequence-harvest only if current reader evidence identifies a one-use event, excess minor-character burden, or unresolved causal debt.

## Anti-choppy implication
Causal density is not sentence density. Do not turn a tighter plot into tighter punctuation.

`CAUSAL MEMORY → SCENE/MODE CHOICE → PARAGRAPH UNIT → SENTENCE RHYTHM`.

An event can have many downstream consequences while being narrated in calm, connected prose.
