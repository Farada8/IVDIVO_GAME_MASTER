# 1. Source architecture

Clark explicitly treats his advice as **tools, not rules** and warns against applying too many tools simultaneously during drafting. The system moves across levels:
- word/sentence/paragraph craft;
- economy, clarity, originality and persuasion;
- blueprints for stories/reports;
- productive writing habits;
- bonus tools such as narrative numbers, short emphasis and inciting incident.

This supports IVDIVO's existing separation between discovery/drafting and targeted revision passes.

# 2. Prose mechanics relevant to the “обрубки” problem

## A. Sentence length controls reader speed
Clark's Tool 18: vary sentence length to influence pace. Long sentences are not errors by default; short sentences are not strength by default.

### IVDIVO transfer
`FUNCTION → DESIRED READER SPEED → SENTENCE SHAPE`.

Use short syntax for impact, clarity under complexity, decisiveness or sudden turn. Use longer syntax when the reader should accumulate perception, causality, contrast or thought before landing.

## B. Paragraph length must match intent
Tool 19 explicitly treats paragraph length as variable: short, long, or a turn according to purpose.

This confirms that a mechanical target such as “reduce 1–4-word paragraphs below X%” cannot be the final criterion.

### Paragraph Intent Audit
For every conspicuously short paragraph:
`WHY IS THIS BREAK HERE?`
- speaker change;
- focus/subject turn;
- time/space shift;
- revelation;
- impact;
- deliberate breath;
- contrast;
- accidental segmentation.

Only accidental segmentation is automatically wrong.

## C. Key words need space — but repetition must be intentional
Tool 12 combines two useful constraints:
- important language benefits from position/space;
- distinctive words should not be repeated accidentally.

### Transfer
White space is an emphasis budget. It should isolate what deserves isolation, not every micro-reaction.

## D. Complexity calls for simplicity, not fragmentation
Tool 11 recommends simpler language/units at moments of conceptual complexity.

For IVDIVO's technical material this suggests:
- keep terminology bounded;
- use concrete example before abstract explanation where possible;
- simplify sentence architecture around genuinely difficult concepts;
- do not simulate clarity by breaking one coherent thought into five disconnected fragments.

## E. Ladder of abstraction
Tool 22: move between abstract and concrete levels; know when to show, tell, or combine.

### IVDIVO use
For systems like Lesson Zero/Lattice:
`CONCRETE EVENT → OBSERVABLE EFFECT → CHARACTER INTERPRETATION → LIMITED ABSTRACT MODEL → RETURN TO CONSEQUENCE`.

This prevents pages of abstract system talk detached from bodies, choices and relationships.

# 3. Story-level mechanisms

## A. Story engine = key question
Clark's Tool 31 defines an engine as the question the action answers for the reader.

This is compatible with, but not identical to, mystery question. A book can contain many local mysteries while one primary engine organizes the whole experience.

### Book Two current engine
The architecture already states a strong form:
**What am I actually responsible for when legitimate authority is finally mine?**

The Lattice/provenance mystery should pressure this engine rather than replace it.

### Gate implication
Every major sequence should either:
- intensify the key question;
- complicate Ethan's possible answer;
- force a choice that partially answers it;
- reveal a consequence of an earlier answer.

## B. Reader rewards / “gold coins”
Tool 32 argues that readers need rewarding high points along the path, especially through the middle.

IVDIVO translation: retention cannot rely only on deprivation, mystery withholding and escalating problems.

### Reward classes
- competence payoff;
- emotional intimacy;
- wonder/discovery;
- humor/social pleasure;
- answer/payoff to an earlier question;
- reversal that makes previous material newly meaningful;
- earned success before a harder consequence.

A middle consisting only of complications creates fatigue.

## C. Internal cliffhangers
Tool 30: propel readers by making them wait.

Limit: waiting must be attached to a meaningful uncertainty, not arbitrary chapter cutting.

Use:
`LIVE QUESTION → INTERRUPTION / CONSEQUENCE → NEXT UNIT HAS DIFFERENT IMMEDIATE TASK BUT PRESERVES QUESTION`.

Avoid:
`sentence cut before answer for no story reason`.

## D. Purposeful repetition
Tool 33 treats repetition as a linking device when purposeful.

Cross-source alignment: Le Guin's developing repetition and McKee's diminishing returns both imply that recurrence must change context/meaning/intensity.

### IVDIVO rule
`REPEAT FORM / IMAGE / ISSUE → CHANGE FUNCTION OR MEANING`.

## E. Scene vs report / narrative modes
Tools 25, 35 and 36 distinguish information delivery from lived experience and encourage mixing modes.

This reinforces existing scene/summary allocation:
- scene for contested choice, relationship turn, discovery-in-action, danger, performance;
- summary/report for orientation, elapsed routine, compressed evidence, repeated pattern.

# 4. Revision process

Clark's broader process model is:
`EXPLORE / COLLECT → FOCUS → SELECT → ORDER → DRAFT → REVISE`.

The most useful IVDIVO addition is **SELECT**. Research volume does not justify inclusion. A sharp focus gives permission to cut fascinating material that does not serve the central meaning/story engine.

This directly applies to the growing craft library itself: source knowledge should improve selection, not force every learned device into every chapter.

# 5. Cross-source comparison

## Clark ↔ Le Guin
Both reject uniform sentence/paragraph rhythm. Clark gives practical pacing labels; Le Guin provides a more literary multi-scale account of rhythm.

## Clark ↔ Hodgins / Provost
All converge on unity/coherence, sentence variation and transitions. The useful synthesis is not “longer paragraphs are better,” but “paragraph boundaries must carry functional continuity or deliberate break.”

## Clark ↔ McKee
Clark's key-question engine is a reader-facing formulation of story propulsion; McKee is stronger on scene value change and causality. Use both: one macro question, causal/value turns locally.

## Clark ↔ LaPlante
Clark's Select/Order/Revisions fit LaPlante's warning against polishing the wrong material. Structural selection comes before micro-polish.

# 6. Failure modes

1. **Shortness Fetish** — assuming short sentence/paragraph = strong prose.
2. **Density Fetish** — assuming long connected paragraphs = mature literary prose.
3. **White-Space Inflation** — isolating every thought until emphasis disappears.
4. **Technical Dump** — abstract explanation without concrete action/consequence.
5. **Engine Drift** — local mysteries/subplots become more prominent than the book's central reader question.
6. **Reward Starvation** — middle only withholds/punishes, giving no competence, intimacy, wonder or partial payoff.
7. **Fake Cliffhanger** — chapter ends by withholding a sentence rather than creating meaningful future uncertainty.
8. **Research Dump** — interesting world/craft material inserted because it exists.
9. **Tool Pileup** — trying to consciously satisfy dozens of craft rules during first drafting.

# 7. New production gates

### Gate HA — Sentence-Speed Fit
Sentence length/complexity must fit desired reader speed and cognitive load.

### Gate HB — Paragraph-Intent Test
Conspicuous paragraph breaks require a functional reason; no arbitrary segmentation.

### Gate HC — White-Space Scarcity
Standalone lines and micro-paragraphs are emphasis resources, not default formatting.

### Gate HD — Complexity Simplification
At difficult conceptual moments, simplify wording/structure without destroying logical continuity.

### Gate HE — Abstraction Ladder
Major abstract explanation must connect to concrete observable detail and consequence.

### Gate HF — One Macro Engine
The book must maintain one dominant reader-facing question even while local mysteries multiply.

### Gate HG — Reader Reward Distribution
Each major middle sequence must contain earned reader rewards, not only escalating deprivation.

### Gate HH — Earned Cliffhanger
A chapter-ending delay must arise from a live story question/consequence, not arbitrary truncation.

### Gate HI — Developing Repetition
Repeated image/theme/argument must alter meaning, stakes, choice or relationship state.

### Gate HJ — Mode Allocation
Choose scene, summary, report, dialogue or compression by dramatic function rather than default density.

### Gate HK — Selection Before Polish
Cut/merge/select material against focus/story engine before line polishing.

### Gate HL — Tool Routing
Do not require every drafting pass to satisfy every craft gate simultaneously; route tools by defect/stage.

# 8. Manuscript validation — LESSON ZERO

## Book One — cadence diagnosis
The existing Book One patch history shows both the original risk and the wrong possible cure: some writer-room versions retained visibly extreme micro-paragraph segmentation, while later development work reduced it. Clark supports the current policy: paragraph and sentence metrics are diagnostics only. The acceptance question is whether each break controls pace, focus and emphasis intentionally.

No whole-book automatic merge pass is authorized.

## Book Two opening — Ch1
The opening uses short lines effectively at high-value places:
- `It was laminated.` turns Ethan's long-running authority obsession into a compact joke;
- the badge text gets visual space because it is the object carrying the chapter's thematic pressure.

Those should not be “fixed” merely because they are short.

However, the early banter plus many short dialogue paragraphs increases white space naturally. Cadence audit should therefore distinguish dialogue-format shortness from narration fragmentation.

## Book Two macro engine
Current handoff/architecture provides a strong engine: legitimate authority and responsibility. Ch1 pays it immediately when the joke badge becomes a real stop decision. Ch2 deepens it through Aaron. This is stronger than opening on the provenance mystery because the mystery is now subordinate pressure on a human question.

## Reader reward distribution — Book Two plan
The architecture already contains several potential gold coins that should be protected:
- Ch6 `THE SYSTEM WORKS` — genuine impressive success;
- Ch9 Ollie's breadcrumb rovers — maker competence;
- Ch10 Ethan genuinely authorizes rather than merely refrains;
- later Lattice must save someone for real, protecting Voss's side of the argument.

These positive/competence rewards are structurally important. Do not cut them for “faster suspense” unless replaced with equivalent reader reward.
