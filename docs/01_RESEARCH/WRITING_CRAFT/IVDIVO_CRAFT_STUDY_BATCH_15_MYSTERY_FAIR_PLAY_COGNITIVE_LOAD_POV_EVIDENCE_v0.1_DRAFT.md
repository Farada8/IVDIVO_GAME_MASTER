# 1. ALICIA RASLEY — POV AS FAIR-PLAY CONTROL

## Source-layer finding

For mystery, POV is not only voice/intimacy. It controls the reader's evidence access.

The useful genre principle is:

`READER and SLEUTH should have access to the same ESSENTIAL information needed to solve the central puzzle.`

This does **not** mean:
- every reader must solve it;
- every clue must be highlighted;
- every secondary POV is forbidden;
- the reader and protagonist must know every irrelevant fact at the same time.

It means the author should not depend on an essential fact that existed offstage and is produced only after the reveal.

### IVDIVO operationalization

For every essential clue:

`CLUE ID | EVENT/TEXT LOCATION | WHO OBSERVES IT | WHAT READER RECEIVES | WHAT HERO RECEIVES | ESSENTIAL? | WHEN INTERPRETED | PAYOFF`

### Failure modes

1. Reader sees an essential fact the sleuth cannot possibly know, yet later the sleuth reasons as if they had it.
2. Sleuth knows an essential fact the narration hides solely to preserve the twist.
3. A late POV supplies the missing answer rather than complicating an already fair evidence set.
4. Too much villain POV collapses uncertainty before the intended reveal.

# 2. JAMES N. FREY — FAIR PLAY AS READER CONTRACT

## Source-layer finding

Frey's `playing fair` rule strengthens the Rasley mechanism:

- clues/facts necessary for a mystery should be offered fairly;
- suspense should not depend on competent characters becoming stupid for plot convenience;
- coincidences may credibly trigger a story but should not solve central problems;
- contrivance occurs when the author gives the characters a solution they did not earn;
- obstacles should be commensurate with protagonist competence.

### Fair-play chain

`PROBLEM → AVAILABLE EVIDENCE → CHARACTER CAPACITY → INTERPRETATION → CHOICE → ACTION → CONSEQUENCE`.

Reject:

`PROBLEM → AUTHOR HIDES / CHARACTER FORGETS / MIRACLE ARRIVES → SOLUTION`.

# 3. LISA ZUNSHINE — MYSTERY AS TRACKING MINDS AND SOURCES

## Source-layer finding A — clues are not cognitively neutral objects

A material clue matters because readers and investigators use it to infer:

- what somebody knew;
- what somebody wanted;
- what somebody believed;
- what somebody intended;
- what somebody tried to hide;
- whether a statement/source can be trusted.

Operational model:

`MATERIAL / BEHAVIORAL CLUE`
→ `SOURCE TAG`
→ `POSSIBLE MENTAL STATE / INTENTION`
→ `COMPETING EXPLANATIONS`
→ `PREDICTION`
→ `TEST`
→ `MODEL UPDATE`.

This is especially relevant to IVDIVO because many mysteries concern institutions, records, interfaces and systems rather than a conventional murderer.

## Source-layer finding B — source monitoring

Readers continuously track not just **what** is known but **who thinks/claims/knows it and how reliable that source is**.

Therefore the mystery ledger must separate:

`FACT`
from
`CLAIM`
from
`INTERPRETATION`
from
`INFERENCE`
from
`RUMOR / MODEL OUTPUT`.

### IVDIVO source tag set

- `OBSERVED` — directly seen/measured within POV access;
- `RECORDED` — comes from a trace/document/log;
- `DECLARED` — participant/source says it;
- `INFERRED` — model or person derives it;
- `INTERPRETED` — meaning assigned to observed material;
- `UNVERIFIED` — claim exists but has not been checked;
- `CONTESTED` — credible sources disagree;
- `WITHHELD BY RIGHT` — information exists but access is legitimately denied.

## Source-layer finding C — cognitive expense

A mystery in which many people may be lying or many knowledge states nest inside one another becomes cognitively expensive. Zunshine's detective-fiction discussion supports the usefulness of narrowing the organizing question so the reader does not need to keep an unbounded matrix of who knows that A thinks B knows C.

### Cognitive-load model

`NUMBER OF ACTIVE SOURCES`
× `NUMBER OF POSSIBLE INTENTIONS`
× `NUMBER OF NESTED KNOWLEDGE STATES`
× `NUMBER OF OPEN QUESTIONS`
= approximate reader tracking burden.

This is not a literal psychometric formula; it is an editorial diagnostic.

### Operational response

When burden rises, reduce or anchor at least one variable:

- fewer active suspects/sources;
- one dominant question per sequence;
- recurring physical clue/object/diagram;
- explicit source labels;
- intermediate partial answer;
- character summary that changes action (not recap for recap's sake);
- close a minor question before opening two new ones.

# 4. JAMES SCOTT BELL — MYSTERY VS SUSPENSE

## Source-layer distinction

Useful working distinction:

- **Mystery** asks what happened / what is true / what will the protagonist discover next.
- **Suspense** asks what will happen to the protagonist / whether an anticipated danger or loss will occur.

They can coexist, but they create different reader engines.

### IVDIVO two-channel ledger

`MYSTERY QUESTION | CURRENT MODEL | CLUE | NEW MODEL`

separate from:

`FUTURE OUTCOME | WHY READER CARES | UNCERTAINTY | CLOCK/PRESSURE | DELAY/OBSTACLE | PAYOFF`.

### Failure mode

A procedural investigation can have many clues but no suspense if nothing important depends on when/how the truth is found.

Conversely, a dangerous deadline can create suspense without producing a satisfying mystery if the later answer was arbitrary.

# 5. JAMES SCOTT BELL — DESIGN FROM THE TRUTH BACKWARD

For a conventional mystery, Bell recommends knowing the crime/truth sufficiently well to work backward to the clues and suspects.

IVDIVO transfer:

Before constructing a long provenance mystery, define a **Truth Box** even if parts remain deliberately UNKNOWN at saga scale.

### Truth Box fields

`WHAT IS ACTUALLY TRUE IN THIS BOOK'S LOCAL CASE?`
`WHAT IS NOT YET DECIDED AT SAGA LEVEL?`
`WHAT FALSE EXPLANATIONS ARE PLAUSIBLE?`
`WHAT PHYSICAL/DOCUMENTARY/BEHAVIORAL TRACES WOULD TRUTH LEAVE?`
`WHICH TRACES CAN BE SHOWN NOW?`
`WHICH MUST REMAIN UNAVAILABLE FOR LEGITIMATE IN-WORLD REASONS?`

The author must never use `UNKNOWN TO AUTHOR` as if it were `MYSTERIOUS TO READER`.

# 6. JESSICA BRODY — YA DETECTIVE MUST BE PERSONALLY CONNECTED

## Source-layer finding

A teen investigator who has no personal connection to the case risks becoming a clue-delivery mechanism. Mystery gains YA force when the hero is both:

- not fully prepared for the investigation;
- personally connected enough that success/failure changes their own life, relationships, status or future.

### IVDIVO test

For every major youth mystery:

`WHY THIS TEEN?`
`WHAT CAN THEY LOSE OTHER THAN ABSTRACT TRUTH?`
`WHAT ORDINARY LIFE DOES THE CASE DISRUPT?`
`WHAT UNIQUE ACCESS OR BLIND SPOT COMES FROM THEIR LIFE?`

# 7. RIBÓ / CHATMAN — SUSPENSE, SURPRISE, EMPLOTMENT

Narrative interest can use both:

- **suspense**: reader anticipates a future possibility from prior information;
- **surprise**: reader lacks the crucial expectation and the event changes the model.

A strong reveal should be surprising in interpretation while remaining retrospectively supported by earlier material.

### Retrospective fairness test

After reveal, reader should be able to say:

`I SAW THAT, BUT I UNDERSTOOD IT DIFFERENTLY.`

Not:

`THERE WAS NO WAY TO KNOW BECAUSE THE AUTHOR NEVER SHOWED IT.`

# 8. CROSS-SOURCE SYNTHESIS — IVDIVO MYSTERY ENGINE v0.2

[OUR SYNTHESIS / DRAFT — NOT CANON UNTIL FOUNDER APPROVAL]

## 8.1 Core evidence cycle

`OBSERVABLE EVENT`
→ `SOURCE TAG`
→ `CLUE`
→ `INITIAL INTERPRETATION`
→ `ALTERNATIVE EXPLANATION`
→ `ACTION/TEST`
→ `CONSEQUENCE`
→ `MODEL UPDATE`
→ `PARTIAL ANSWER`
→ `NEW QUESTION`.

## 8.2 Reveal quality

A reveal is strong only if it changes at least one of:

- next action;
- target;
- risk;
- relationship;
- access;
- authority;
- moral judgment;
- time pressure;
- interpretation of earlier evidence.

`REVEAL WITH NO CONSEQUENCE = LORE DELIVERY`.

## 8.3 Red herring rule

A fair red herring is preferably:

`TRUE OBSERVATION + PLAUSIBLE WRONG INTERPRETATION`.

Avoid:

`FALSE FACT INSERTED BY AUTHOR solely to mislead reader`.

## 8.4 Knowledge-state ledger

For every sequence:

`FACT | ETHAN KNOWS | SAMIR KNOWS | AОIFE KNOWS | MAYA KNOWS | OLLIE KNOWS | ADULTS KNOW | READER KNOWS | LATTICE CLAIMS/INFERS | SOURCE RELIABILITY`.

Only track fields that matter to the current question; do not turn the novel into bookkeeping.

# 9. NEW PRODUCTION GATES

[OUR SYNTHESIS / DRAFT — NOT CANON UNTIL FOUNDER APPROVAL]

### Gate DV — Reader/Sleuth Essential-Information Parity
The reader and active investigator must have access to the essential evidence required for the intended inference, unless an explicit POV design intentionally makes the reader the detective.

### Gate DW — Clue Before Conclusion
No major conclusion may precede the observable evidence that could support it.

### Gate DX — Source Tag
Every important mystery statement must be classifiable as observed, recorded, declared, inferred, interpreted, unverified, contested, or withheld by right.

### Gate DY — Alternative Explanation
Before promoting a clue to proof, name at least one credible alternative explanation or explain why alternatives have been eliminated.

### Gate DZ — Red-Herring Integrity
Prefer truthful evidence misread plausibly over fabricated misinformation inserted only to fool the reader.

### Gate EA — Cognitive Load Budget
Do not maintain more simultaneous source/intent/knowledge-state branches than the sequence can keep legible.

### Gate EB — Material-to-Mind Bridge
A physical/data clue must matter because it changes a hypothesis about behavior, intention, knowledge, system rule or causal history.

### Gate EC — Reveal Consequence
Every significant reveal must alter action, relationship, authority, risk, target, clock or model.

### Gate ED — No Retroactive Essential Fact
The final explanation may reinterpret old evidence but may not depend on an essential fact introduced only after the solution is announced.

### Gate EE — Mystery/Suspense Separation
Track the puzzle question separately from the feared/desirable future outcome.

### Gate EF — Youth Personal Connection
The youth investigator must have a personal stake/access/blind spot that makes them necessary rather than a generic clue courier.

### Gate EG — Truth Box
Before long-form clue architecture, define what is locally true, what is saga-unknown, and what traces the truth would realistically leave.

### Gate EH — Partial Closure
Long mysteries must periodically close subordinate questions so cognitive burden does not only accumulate.

# 10. MANUSCRIPT VALIDATION — BOOK TWO PROVENANCE THREAD, CH1–6

## Ch1 — Taven/Mel route divergence

### Observable evidence
- declared companions receive divergent routes;
- interface still says continuity maintained;
- Taven articulates that one of them was expected to correct the divergence;
- after stop, mode changes to explicit coupling.

### Fair interpretation
The routing system predicts/uses probable companion behavior.

### Not yet justified
- that the system is malicious;
- that it copied R-14;
- that historical lineage is causal rather than convergent;
- that Confederation technology is the source.

**PASS DV/DW/DY.** The text keeps observation ahead of ontology.

## Ch1 — Samir says he knows the shape

This is a good mystery hook because he immediately bounds it:

`not a match` + `not random`.

It opens a comparison without claiming identity.

**Protect.** Do not let Ethan jump straight to Root Library certainty.

## Ch3 — declared vs inferred relations

This is an important clue because it changes the current-system question before it changes the historical question.

Correct sequence:

`PUBLIC BEHAVIOR PROBLEM → MODEL VARIABLE DISCOVERY → HISTORICAL STRUCTURAL COMPARISON`.

This prevents provenance lore from swallowing the live Rivergate case.

## Ch3 — actor order

`same actors + same final position + different order → different next state` is a strong formal clue.

However, at present it is only a **structural similarity**, not a provenance proof.

Required ledger status:

`OBSERVED + COMPARED + NON-UNIQUE UNTIL TESTED`.

## Ch3 — Voss's response

Her interest in possible inherited assumptions creates an ethically serious adult ally rather than a cover-up stereotype.

This improves fair play: adult competence does not have to be artificially removed for teenagers to investigate.

## Ch6 — system success

The Lattice prevention event is not a provenance clue. It is a suspense/moral-stakes asset.

Keep ledgers separate:

- Mystery: `where did this relational design assumption come from / what exactly is being inherited?`
- Suspense: `what happens if a genuinely useful system is halted or allowed to keep concentrating burden?`

Conflating these would make every system behavior feel like a clue and overload the reader.
