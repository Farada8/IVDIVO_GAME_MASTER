## 1. Production scope

The visual package is built around the actual board/product architecture:

- 64 real-place location nodes;
- 8 Portal nodes;
- shared map of Ireland / North Atlantic route layer;
- travel, route and collection play;
- Sparks, Keys and Light;
- active characters from the current character register;
- Artifacts/Treasures only when taken from the active component/card register;
- 2.5D browser scenes derived from the same art records.

The art team must not use the unrelated standalone 24-Portal card list as source data.

## 2. Required order of work

### Phase A — lock data

1. Populate the 64-location and 8-Portal register.
2. Confirm every name and real-place reference.
3. Mark each lore field as `FACT`, `TRADITION`, `ALTERNATIVE HYPOTHESIS`, or `GAME FICTION`.
4. Record each location's mechanical function and route relation.
5. Select the current user-approved style references.

### Phase B — visual direction tests

Generate only eight location tests and two Portal tests before producing the full set. Test:

- emerald freshness;
- Atlantic light;
- colour contrast;
- tactile stone, grass, water, metal and crystal;
- mystical intensity;
- historical recognisability;
- card-size readability;
- suitability for 2.5D separation;
- consistency with the supplied references.

### Phase C — production

1. Produce 64 location illustrations from exact register rows.
2. Produce 8 Portal illustrations from exact register rows.
3. Produce character illustrations from the active character register.
4. Produce Artifact/Treasure illustrations only from the active item register.
5. Produce map, box, Kickstarter and 2.5D derivative assets from selected production art.

## 3. Canonical prompt record

Every finished prompt record must include:

`id, type, canonical_name, real_place, county_region, historical_anchor, tradition, alternative_hypothesis, game_fiction, mechanic_role, route_role, portal_link, carrier_object, focal_scene, palette, contrast, lighting, textures, mood, composition, 2_5d_layers, aspect_ratio, style_reference, seed, negative_prompt, source, status`

A prompt is blocked when the canonical row is incomplete.

## 4. Location prompt template

Use only after the exact location row is populated.

```text
[STYLE REFERENCES], premium mystical travel-adventure illustration for «Portals: Sparks of the Archipelago», [LOCATION ID] — [CANONICAL NAME], recognisably based on the real place [REAL PLACE, COUNTY/REGION], historically accurate visible anchors: [HISTORICAL / ARCHAEOLOGICAL / LANDSCAPE DETAILS], documented tradition or local memory: [TRADITION], alternative hypothesis presented visually as possibility rather than fact: [ALTERNATIVE HYPOTHESIS], exact gameplay role: [MECHANIC ROLE], route function: [ROUTE ROLE], focal carrier object: [CARRIER OBJECT], strong single visual story readable at board and card size, premium mystical realism, luminous Atlantic atmosphere, fresh emerald greens, deep ocean and mineral colours, controlled warm-gold highlights, high clean contrast, tactile textures of [MATERIALS], layered foreground / middle ground / background suitable for 2.5D parallax, mysterious and intellectually captivating, historically recognisable, not dry museum illustration, not childish cartoon, not generic fantasy, no text, no UI, no invented monuments, no random pseudo-Celtic symbols --ar [RATIO] --stylize [VALUE]
```

## 5. Portal prompt template

A Portal is not merely a glowing ring. It must be a mechanically readable threshold tied to an exact location and route function.

```text
[STYLE REFERENCES], premium Portal-node illustration for «Portals: Sparks of the Archipelago», [PORTAL ID] — [CANONICAL PORTAL NAME], anchored in [REAL PLACE / LINKED LOCATIONS], historically recognisable carrier structure: [CARRIER OBJECT], documented cultural memory: [TRADITION], speculative mystical reading: [ALTERNATIVE HYPOTHESIS], exact Portal mechanic: [COST / ACCESS / RISK / DESTINATION / BENEFIT], show the moment the threshold becomes usable, one unmistakable route connection, luminous energy integrated into stone, landscape, weather or ancient technology rather than pasted-on neon, emerald Atlantic palette with [PORTAL-SPECIFIC COLOURS], strong contrast, tactile [MATERIALS], cinematic but board-readable, layered for 2.5D animation, no generic sci-fi ring, no random runes, no text, no UI, no invented historical claim --ar [RATIO] --stylize [VALUE]
```

## 6. Character prompt rule

Characters are generated only from the active character register. The prompt must visually communicate the existing gameplay ability, travel role and cultural context. No new powers, weapons, companions, titles or biographies are added by the art prompt.

## 7. Artifacts and Treasures

Artifacts/Treasures belong to the current family-core direction as usable items and discoveries. They are not removed. However, their visual prompts must be generated only after the active item list is selected.

Required item fields:

`item_id, canonical_name, item_type, source_location, historical_material_anchor, mystical_interpretation, exact_game_effect, usage_moment, materials, scale, silhouette, status`

The image must show what the item does in play. Decorative objects without a mechanical or narrative role do not enter the production pack.

## 8. 2.5D requirements

Each selected environment is prepared as separable layers:

1. sky / weather;
2. far landscape;
3. main real-place silhouette;
4. route and playable foreground;
5. Portal or active object;
6. particles / mist / light;
7. optional character/token layer;
8. UI-safe empty zone.

The main visual must still work as a printed board/card illustration without animation.

## 9. Quality gates

Reject an image when:

- the real place is no longer recognisable;
- the mystery looks like an asserted historical fact;
- the Portal is generic and unrelated to the mechanic;
- green dominates as a tourist cliché rather than a controlled palette;
- detail disappears at final print/mobile size;
- Celtic ornament is generic, random or culturally misplaced;
- the composition cannot be separated for 2.5D;
- the result looks like children's cartoon art, grimdark horror or plastic sci-fi;
- the image introduces a location, artifact, technology or character not present in the active register.
