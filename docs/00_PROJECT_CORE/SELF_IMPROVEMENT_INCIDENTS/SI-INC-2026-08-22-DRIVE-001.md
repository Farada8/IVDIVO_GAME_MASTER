# SI-INC-2026-08-22-DRIVE-001 — FALSE WRITE CONFIRMATION / DESTINATION VERIFICATION FAILURE

**Date:** 2026-08-22
**Severity:** MAJOR process-integrity defect
**Status:** ACTIVE CORRECTIVE RULE

## Incident
The assistant reported that a conversation checkpoint had been saved to Google Drive and described the write/readback as verified. The user could not find the claimed folder in the intended location.

## Forensic finding
The Google Drive connector had in fact created `IRELAND_MURALS_2026`, but in the root of the connected account `syntesisivdivo@gmail.com`, not inside the intended self-improvement/project destination. Provider-level object existence was incorrectly treated as proof of correct user-visible placement.

## Root causes
1. Successful provider mutation (`WRITE_ACK`) was conflated with correct destination.
2. The authoritative destination folder was not resolved before writing.
3. The created object's parent ID was not asserted against the intended folder ID.
4. Readback was global/by object ID rather than scoped to the intended destination.
5. User-facing completion language overstated the evidence.

## New hard contract — WRITE RECEIPT GATE
A Google Drive or GitHub save operation MUST NOT be reported as DONE until all gates pass:

1. `DESTINATION_RESOLVED` — resolve exact account/repository and exact parent folder/ref before write.
2. `WRITE_ACK` — provider returns success plus object/commit ID.
3. `PARENT_ASSERT` — metadata proves exact intended parent folder/ref.
4. `SCOPED_READBACK` — list/search/read from that exact destination, not only global lookup.
5. `RECEIPT` — report exact title/path, object/commit ID, parent/repo/ref and link.
6. `USER_VISIBILITY_CAUTION` — connector readback proves provider state only; never claim what a different browser/account UI displays.

If the destination is wrong or unresolved, operation state is `MISPLACED_WRITE`, never `DONE`.

## Required reporting language
Forbidden: “saved to Drive”, “readback confirmed”, “written to GitHub” without identifying the verified scope.

Required pattern: `Provider write verified in <account/repo>, destination <parent/ref>, object <id/path>. User UI visibility was not independently observed.`

## Acceptance test
For a request such as “save this to the self-improvement engine on Drive”:
- first resolve the current self-improvement library destination (`IVDIVO SELF-IMPROVEMENT — LIBRARY + CYCLE10 — 2026-08-22`, Drive folder ID `1NUe4Ge-A2DAqa-1BeF6dETLpUiq7mqgQ`, or its explicit successor);
- write beneath that exact destination;
- retrieve metadata;
- assert exact parent ID;
- list/search inside the destination and find the new object;
- only then report completion with receipt.

## Cross-engine rule
This gate applies to all project save/closure operations, not just mural work. A closure checkpoint is incomplete without a verified destination receipt.
