# IVDIVO — PROJECT-WIDE CONTINUATION LAW

**Status:** CANONICAL OPERATIONAL LAW — FOUNDER APPROVED  
**Version:** 1.1  
**Approved:** 2026-08-21  
**Updated:** 2026-08-21  
**Scope:** all IVDIVO project conversations, books, story lines, production systems, prompts, engines, programs, procedures and cross-model workflows.

## Founder-approved law

Any substantial result produced in one IVDIVO project conversation is a candidate for project-wide system improvement.

At the next substantive work session, the Router must inspect relevant newer sibling Project conversations and their persisted artifacts for stronger decisions, mechanisms, prompts, programs, procedures, tests, repair laws, production methods or cross-model workflows.

If a discovered result is demonstrably stronger, compatible with higher authority and reusable beyond its source context, the Router must not leave it trapped in that one conversation. It must be considered for integration into the relevant CURRENT layer:

`CURRENT prompts / engine / programs / procedures / handoff state / machine-readable project state`.

## Promotion test

A sibling-dialog result may be promoted only after:

`DISCOVER -> LOCATE PERSISTED ARTIFACT -> VERIFY STATUS/VERSION/HASH/GATES -> COMPARE AGAINST CURRENT -> ABSTRACT PROJECT-SPECIFIC CONTENT -> RED TEAM / REGRESSION AS NEEDED -> CLASSIFY -> PROMOTE OR HOLD OR REJECT -> UPDATE CURRENT POINTERS`.

Classification:
- `PROJECT_ONLY`;
- `GENRE_OVERLAY_CANDIDATE`;
- `UNIVERSAL_CANDIDATE`;
- `REFERENCE_ONLY`;
- `SUPERSEDED`;
- `REJECTED`.

## CHAT-ONLY RESULT INGESTION LAW

A substantial result that exists only inside a conversation and has not yet been persisted is not discarded, but it is not authority.

Classify it as:
- `DISCOVERY_ONLY` when only the existence/claim is known;
- `CHAT_ONLY_CANDIDATE` when the actual result text/data can be retrieved from the source conversation;
- `UNRECOVERABLE_CHAT_ONLY` when the result is known to have existed but its actual content cannot be retrieved reliably.

Required ingestion route:

`DISCOVER CHAT-ONLY RESULT -> IDENTIFY SOURCE CONVERSATION / PROJECT / DATE / TASK -> RETRIEVE ACTUAL RESULT IF ACCESSIBLE -> EXTRACT EXACT MATERIAL DELTA -> MARK PROVENANCE -> COMPARE AGAINST CURRENT AUTHORITY -> VALIDATE CANON / VERSION / HASH / GATES WHERE APPLICABLE -> CLASSIFY -> PERSIST AS CANDIDATE ARTIFACT -> RUN REQUIRED QA / RED TEAM / REGRESSION -> PROMOTE / HOLD / REJECT -> UPDATE CURRENT STATE / HANDOFF / POINTERS -> READBACK VERIFY`.

### Processing rules

1. A memory, summary or statement that “another chat did this” is not enough for promotion.
2. If the actual sibling-conversation content is accessible, retrieve it before asking the Founder to repeat it.
3. If only a summary is accessible, preserve it as `DISCOVERY_ONLY` and do not silently reconstruct missing details.
4. If actual result content is recovered, save the minimum sufficient source material or normalized artifact with provenance before downstream use.
5. Recovered chat-only content enters as `CANDIDATE / UNVERIFIED` unless it can be matched to an already accepted persisted artifact.
6. Never let a chat-only result overwrite a newer accepted persisted artifact merely because the conversation happened later.
7. If the recovered result is stronger but conflicts with current authority, route to `FRONTIER_CONFLICT / AUTHORITY_RECONCILIATION`; do not auto-merge.
8. If the recovered result is valid and materially useful, write it through to the actual controlling engine/prompt/program/project state so future conversations no longer depend on chat retrieval.
9. After successful persistence and readback verification, remove the `CHAT_ONLY` condition; the artifact is then governed by its normal status (`WORKING / ACCEPTED / CURRENT / etc.`).
10. If retrieval is impossible, record the gap and continue from verified persisted state rather than inventing the missing work.

### No-loss objective

The engine should attempt to salvage valuable work from conversations, but authority requires persistence and verification.

Therefore:

`CHAT MEMORY IS A DISCOVERY SURFACE; PERSISTED VERIFIED ARTIFACTS ARE THE EXECUTION SURFACE.`

The Founder should not have to manually copy a recoverable result from one dialogue to another when the system can retrieve and persist it itself.

## Authority protection

This law does not allow a sibling chat to override higher authority merely because it is newer.

Priority remains:
1. Founder newest direct instruction;
2. locked/approved project and saga canon;
3. current domain authority;
4. verified current project source-of-truth / execution state;
5. accepted working artifacts;
6. candidate mechanisms;
7. references/archive.

A sibling-chat statement that has not been persisted/verified is `DISCOVERY_ONLY`, not authority.

## No duplication law

Do not create parallel routers or duplicate engines merely because a useful mechanism was found elsewhere.

Prefer:
`DISCOVER -> RECONCILE -> UPGRADE EXISTING CURRENT AUTHORITY`.

Create a new universal file only when it represents a genuinely distinct reusable contract.

## Cross-model application

The same law applies to work produced with ChatGPT, Claude, Grok, Codex or other models.

Model output becomes only candidate evidence until reconciled. Accepted findings must be applied to the actual controlling artifact/state and verified before they count as integrated.

If an external-model result exists only in a chat/session transcript, process it through the same `CHAT_ONLY_CANDIDATE` ingestion route before promotion.

## Continuation behavior

When the Founder opens any IVDIVO project conversation or gives a continuation command, the Router should not merely resume the local chat. It should:

1. restore persisted project state;
2. delta-scan newer relevant sibling-dialog artifacts;
3. inspect relevant chat-only discoveries when recoverable and materially capable of changing the next action;
4. ingest/persist recoverable chat-only candidate results before relying on them;
5. identify stronger compatible reusable mechanisms;
6. integrate/promote them when justified;
7. recompute the dependency DAG;
8. execute the highest unblocked obligation;
9. continue through further unblocked stages until a real gate stops the work;
10. persist the new frontier and any promoted system improvements.

## Final law

**THE PROJECT LEARNS ACROSS ITS CONVERSATIONS.**

**A BETTER VERIFIED MECHANISM DISCOVERED ANYWHERE IN IVDIVO SHOULD NOT REMAIN TRAPPED IN ONE CHAT.**

**A VALUABLE CHAT-ONLY RESULT SHOULD BE RECOVERED, VERIFIED AND PERSISTED — NEVER SILENTLY TREATED AS AUTHORITY AND NEVER NEEDLESSLY LOST.**
