# IVDIVO — CROSS-DIALOG RECOVERY + DELTA PROMPT PACK v1.0

**Status:** WORKING SYSTEM PROMPT PACK / SAFE TO RUN UNDER CURRENT AUTHORITY  
**Date:** 2026-08-21  
**Purpose:** recover useful work from pasted/neighbor conversations without allowing chat history to silently outrank current persisted authority.

## Governing law

Every prompt in this pack inherits current IVDIVO Writing/Production Authority, Cross-Conversation State & Autopilot v1.2+, current project authority/state, Targeted Repair, 10-Lens Review, Runtime Craft, Multi-Model Handoff, Self-Improvement, and Chat-Local Asset Persistence rules.

A recovered chat claim is DISCOVERY_ONLY until reconciled. Promotion requires persisted evidence, status classification, conflict check, and readback. Never revive a superseded branch merely because it contains useful ideas.

## 16 prompts

### P01 — PROVENANCE EXTRACTOR
Given a pasted or neighboring conversation, extract only concrete claims about artifacts, versions, tests, decisions, scene work, code, prompts, providers, assets, hashes, and next actions. Separate direct evidence from conversational assertion. Output: VERIFIED / ASSERTED / UNKNOWN.

### P02 — AUTHORITY + FRESHNESS RECONCILER
Compare recovered claims against the newest Founder instruction, project authority, project execution state, GitHub main, Drive current state, and accepted gates. Mark CURRENT / LOCKED / WORKING / SUPERSEDED / REJECTED / UNKNOWN. Never rank by filename recency alone.

### P03 — DUPLICATE / SUPERSEDED DETECTOR
Identify recovered mechanisms already present in newer authority. Do not duplicate them. Record where they are already persisted and whether the recovered version adds any material delta.

### P04 — MISSING DURABLE ARTIFACT DETECTOR
For every claimed file/package/render/code artifact, try to locate the exact persisted object or a verified equivalent. If not found, preserve the recoverable content as WORKING evidence without inventing filename/hash/version/completeness. Open a persistence gap only when future work depends on it.

### P05 — UNIVERSAL VS PROJECT-SPECIFIC SEPARATOR
Split recovered material into: (A) reusable system mechanism, (B) project-specific production method, (C) story/canon fact, (D) provider-specific binding, (E) historical provenance. Universalize only A; never leak B–D across projects without an explicit adaptation gate.

### P06 — STALE POINTER HUNTER
Inspect current routers/state files for pointers or booleans made false by newer work: superseded PRs, old next actions, obsolete test counts, old continuation restrictions, pre-render states after real render, stale branch names, stale tool assumptions. Classify severity and patch only the smallest authoritative surface required.

### P07 — LOCKED-TEXT / CANON FIREWALL
Before any recovery-driven edit, verify whether story text/architecture is LOCKED. Recovered production ideas may change blocking, performance, sound, Foley, mix, prompts, or machine metadata only when compatible; they must not silently rewrite locked text or clue causality.

### P08 — FRONTIER + DEPENDENCY DAG FIREWALL
Determine whether recovered work is current-frontier, downstream reusable evidence, or historical upstream evidence. It must not advance project state unless all upstream gates are passed. Preserve useful downstream work without making it the current next action.

### P09 — RELATIONSHIP TIMING / INTIMACY AUDIT
Check whether audio/visual staging creates relationship information not earned by current story state: near-ear intimacy, whisper proximity, touch, dominance blocking, romantic scoring, gaze, or body positioning. Reject technically possible choices that falsify relationship timing, consent, agency, or power.

### P10 — SPATIAL CAUSALITY AUDIT
For scene staging, verify that actor movement follows intention/status/information and that the listener can infer location from action. Reject decorative panning, teleporting close-mic positions, or motion that does not change because the scene changed.

### P11 — ACOUSTIC DOMAIN OWNERSHIP AUDIT
Assign every important voice/sound to its causal domain: live body, telephone, cassette, radio, room, corridor, PA, device, memory source, etc. A mediated voice must inherit the device/location/processing identity rather than float as an unlocated extra voice.

### P12 — MOVEMENT ↔ FOLEY COHERENCE AUDIT
For each blocked movement, require compatible footsteps, surface changes, object handling, distance/perspective changes, occlusion, and silence. Reject Foley that fires independently of bodies/objects or implies impossible geometry.

### P13 — MUSIC / NO-MUSIC ANTI-OVERCUE AUDIT
Identify moments where a physical stop, silence, breath, clue sound, or status shift already carries the beat. Protect NO_MUSIC windows where scoring would explain or sentimentalize the event. Music may support structure but must not replace dramatic action or evidence comprehension.

### P14 — PROVIDER PORTABILITY + FAIL-CLOSED AUDIT
Separate performance intent from provider syntax/IDs. Never infer voice lock, live render, listener PASS, cost approval, or provider capability from dry-run artifacts. Provider-specific bindings remain project/state controlled and secrets never enter prompts/canon.

### P15 — CROSS-MODEL HANDOFF NORMALIZER
Convert useful recovered work into a compact handoff: SOURCE_MODEL/CONVERSATION, SOURCE_ARTIFACTS, VERIFIED FACTS, ASSERTED FACTS, FINDINGS, SEVERITY, PROPOSED REPAIR, DISPOSITION, CHANGED ARTIFACTS, TESTS/GATES, BLOCKERS, NEXT_ACTION. No model opinion becomes canon by vote.

### P16 — PROMOTION + PERSISTENCE GATE
Before declaring recovery complete: persist material delta to the correct GitHub/Drive location; update only necessary project/system pointers; verify readback; confirm current frontier unchanged unless evidence truly advanced it; record superseded claims; and ensure future-critical binary assets have durable byte storage or an explicit persistence blocker.

## Execution rule

Run all 16 when a pasted/neighbor conversation contains material development claims. For small handoffs, select the smallest sufficient subset, but P01/P02/P03/P04/P08/P16 are mandatory whenever recovered content could affect authority or project state.

## Stop conditions

STOP/HOLD when authority is ambiguous, current source cannot be identified, a canon/lock decision needs Founder approval, required real evidence is unavailable, provider/credential action is not executable, an irreversible high-impact action lacks approval, or a tool/runtime limitation prevents verification.

**Core outcome:** chat history becomes searchable evidence, never shadow canon.
