# IVDIVO SELF-IMPROVEMENT ENGINE v3 — CANDIDATE ARCHITECTURE

**STATUS:** CANDIDATE — NOT CURRENT AUTHORITY
**INHERITS:** Self-Improvement v2 VERIFIED_CURRENT

## Control architecture
S5 IDENTITY/AUTHORITY — Founder newest instruction, canon hierarchy, STORY FIRST, character truth, evidence firewall, cost/reversibility laws.

S4 INTELLIGENCE/FUTURE — reference ingest, experiments, external evidence, model/API changes, alternative architectures, expected information gain.

S3 CONTROL/RELIABILITY — fitness/evaluation gates, SLO/error-budget concepts, regression, provenance, rollback, policy-resistance checks.

S2 COORDINATION/FLOW — freshness/rebase, concurrency, dependency graph, queue/WIP control, batch size, routing, cross-chat handoff.

S1 PRODUCTION — books, story architecture, scripts, audio, images, production artifacts and user-facing outcomes.

## Learning plane
`OBSERVE → DEFINE DECISION → CAUSAL HYPOTHESIS → CURRENT UNCERTAINTY → VALUE OF INFORMATION / COST OF DELAY → SMALLEST REVERSIBLE EXPERIMENT → FITNESS + GUARDRAILS → CANARY → MEASURE → CAUSAL UPDATE → PROMOTE / HOLD / ROLLBACK → UPDATE ROUTER`

## Required distinctions
activity != progress
prompt count != product quality
internal score != human/market evidence
correlation != causation
measurement != certainty
local improvement != system improvement
model agreement != independent evidence
single-loop patching != double-loop learning
backlog size != active WIP
reference mechanism != CURRENT authority

## Double-loop escalation
Trigger when the same failure recurs after local repairs, guardrails repeatedly degrade, observed behavior contradicts the causal model, a gate repeatedly blocks useful production without evidence of protection, or a metric no longer changes a meaningful decision.

## Self-application
v3 candidate must pass its own change contract. It cannot become CURRENT merely because the reference corpus is strong.
