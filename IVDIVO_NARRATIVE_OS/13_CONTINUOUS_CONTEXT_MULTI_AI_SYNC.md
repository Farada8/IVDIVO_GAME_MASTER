# IVDIVO CONTINUOUS CONTEXT + MULTI-AI SYNCHRONIZATION PROTOCOL

**Status:** CANONICAL OPERATING SUPPLEMENT  
**Version:** 1.0  
**Established:** 2026-08-21  
**Parent:** `00_NARRATIVE_OS_CANON.md`  
**Applies to:** books, story engines, audio production, visual adaptation, research, external AI review, project handoffs

---

# 0. PURPOSE

IVDIVO work must not depend on the Founder remembering which conversation produced the best latest rule.

A conversation is temporary. Accepted project state and accepted production learning must be persisted and discoverable by the next conversation.

This protocol adds a mandatory **delta-sync layer** before substantive IVDIVO work when connected project state can materially affect the answer.

The Founder does **not** need to type `и / дальше / продолжай` for synchronization to occur. Those commands remain valid shortcuts, but any substantive IVDIVO request should restore current authority and inspect relevant deltas before acting.

This is not background execution. Work still runs when a conversation/task is invoked; the protocol removes the need for the Founder to manually restate already-persisted context.

---

# 1. OPERATING CHAIN

`FOUNDER REQUEST`
→ `ACTIVE PROJECT IDENTIFICATION`
→ `AUTHORITY RESTORE`
→ `BOUNDED DELTA SCAN`
→ `DELTA CLASSIFICATION`
→ `SEMANTIC DEDUPLICATION`
→ `INTEGRATION DECISION`
→ `WRITE-THROUGH / STATE UPDATE`
→ `ROUTE HIGHEST UNBLOCKED OBLIGATION`
→ `EXECUTE`
→ `REGRESSION AS NEEDED`
→ `PERSIST DONE / STATUS / NEXT`

Do not perform a giant audit on every turn. Scan only surfaces that can materially change the current decision.

---

# 2. REQUIRED DELTA SOURCES

When relevant and available, A00 checks:

1. Founder’s newest instruction and current conversation.
2. Active project current authority / source-of-truth / DRAFT_STATUS / build state.
3. Relevant Project/conversation handoffs and shared memory for the same project.
4. GitHub canonical repository changes since the last verified sync point.
5. Google Drive current routers, working frontiers, prompt/program indexes and recently modified project authorities.
6. Current prompt/program authority indexes.
7. Relevant Library / Story Engine / Source Passport / Mechanism Bank changes.
8. Actual external AI outputs from Claude, Grok or another model when they exist.
9. Actual specialist/human/beta/listener evidence when it exists.
10. Domain Learning Registry entries produced by completed projects.

If a source is unavailable, record `UNKNOWN / SOURCE_UNAVAILABLE`; do not reconstruct it from model confidence.

---

# 3. DELTA CLASSIFICATION

Every material new item is classified before adoption:

- `PROJECT_CANON_CHANGE` — belongs to one project/book/season and may not leak elsewhere.
- `STATUS_FRONTIER_UPDATE` — changes what is done/next but not craft law.
- `UNIVERSAL_MECHANISM_CANDIDATE` — abstract process/craft mechanism that may generalize.
- `PROMPT_PROGRAM_UPGRADE` — improves routing, prompts, validation, state safety or execution.
- `EXECUTION_TOOLING_UPGRADE` — improves manifests, compilers, QC, handoff or provider execution.
- `EXTERNAL_EVIDENCE` — Claude/Grok/specialist/human/market evidence.
- `REFERENCE_LEARNING` — abstract mechanism learned from books/scripts/craft/reference sources.
- `DUPLICATE` — same semantic information already recorded.
- `SUPERSEDED` — replaced by a newer accepted authority.
- `REJECTED` — evaluated and not adopted.

Then assign one decision:

`ADOPT_PROJECT / UNIVERSALIZE / ACCEPT_WITH_MODIFICATION / HOLD_FOR_TEST / REJECT / SUPERSEDE`.

A file merely existing is not evidence that its contents are current or valid.

---

# 4. SEMANTIC DEDUPLICATION / ANTI-ECHO LAW

The same idea repeated in several chats, files or models does not gain evidentiary weight merely by repetition.

Before counting agreement:
- determine whether sources are genuinely independent;
- detect mirrors/duplicates/derived summaries;
- group semantically equivalent findings under one `delta_cluster_id`;
- preserve the strongest primary evidence/provenance.

Two models making the same unsupported guess is not triangulation.
Two copies of the same book/file do not increase reference weight.

---

# 5. CROSS-MODEL EVIDENCE LAW

Claude, Grok, GPT and other models are reviewers/tools, not canon authorities.

For high-value cross-model checks:

1. **Source parity:** give models the same current raw/authoritative material where comparison requires parity.
2. **Inventory before judgment:** establish what actually exists in source before grading it.
3. **Citation/evidence requirement:** unsupported confident reconstruction is `NOT VERIFIED`.
4. **Independent roles:** use orthogonal jobs rather than duplicate generic opinions.
5. **No voting:** compare causal evidence, not number of models agreeing.
6. **Diagnosis separate from cure:** a valid defect diagnosis does not automatically validate the reviewer’s proposed rewrite.
7. Every incoming recommendation is classified `ACCEPT / ACCEPT WITH MODIFICATION / HOLD FOR TEST / REJECT` before any canon/script change.

Recommended orthogonal roles when useful:
- development/causality/continuity Red Team;
- cold reader/listener/comprehension/retention attack;
- prosecution-vs-defence or strongest-innocent-alternative attack for mysteries;
- anti-generated-dialogue / voice convergence attack;
- narrow domain specialist review;
- real target-audience Human Signal.

---

# 6. UNIVERSALIZATION FIREWALL

Cross-project learning transfers only abstract mechanisms/process improvements.

Never transfer without explicit authority:
- names or identities;
- provider voice IDs;
- culprit/solution;
- distinctive clue chain;
- chronology;
- signature motif or melody;
- unique scene sequence;
- project-specific relationship timing/state;
- proprietary terminology;
- obsolete branch facts.

Use:

`PROJECT RESULT -> ABSTRACT MECHANISM -> REMOVE DISTINCTIVE CONTENT -> TEST GENERALITY -> UNIVERSAL RECORD -> REBIND THROUGH ACTIVE PROJECT AUTHORITY`.

---

# 7. REFERENCE / BOOK LEARNING LAW

Books, scripts, films, manga, comics and craft texts are references, not story canon.

Use the Story Engine / Source Passport discipline:
- distinguish full source from fragment/demo/collection/scan-unavailable;
- do not infer ending architecture from an opening fragment;
- duplicate copies do not increase evidence weight;
- record mechanism function, emotional effect, abstract formula, failure mode, cliché/copy risk;
- combine independent mechanisms where useful;
- transform through current hero, setting, conflict and world pressure;
- run source-distance/originality check before application.

Preferred mechanism form:

`HUMAN TASK/WANT -> RULE/PRESSURE -> OBSERVABLE CONSEQUENCE -> MODEL UPDATE -> HARDER CHOICE`.

---

# 8. SELECTIVE INVALIDATION LAW

When a universal or project rule changes, do not restart the whole pipeline.

Repair the earliest genuinely failed layer and invalidate only true descendants.

Examples:
- character contract change -> affected P51 fingerprint -> affected dialogue/prose -> aggregate voice regression;
- midpoint/climax/emotional-function change -> affected P52 map -> affected scenes -> final gate;
- relationship authority change -> affected P53 routing/scenes only;
- clue order change -> affected causal scene cards/prose, not unrelated voice states;
- scene-only regeneration -> preserve sibling scene hashes and reopen only necessary aggregate gates.

Locked unrelated artifacts remain stable.

# 9. UNIVERSAL LEARNINGS PROMOTED FROM CURRENT PROJECTS

The following abstract improvements are accepted as universal production mechanisms because they have repeated practical value across current IVDIVO projects.

## Story / character / dialogue
- `STORY FIRST. CHARACTER SECOND. WORLD THROUGH STORY. SAGA THROUGH COMPLETED BOOKS.`
- P51 voice fingerprints are universal for important speaking characters.
- P51 must also scan **shared rhetorical construction families** across different characters; repeated authorial geometry can create voice convergence even when vocabulary differs.
- P52 emotional range is about contrast, not constant escalation.
- P53 relationship control is two-axis: inherited relationship authority + current scene function. Proximity or vulnerability cannot invent attraction.
- Human Signal cannot be simulated internally.

## Audio casting
- Cast the voice that can perform the character contradiction, not the prettiest voice.
- Compare candidates loudness-matched, dry, without music/reverb.
- Test `NATURAL/RESTRAINED -> ONE PRECISE DIRECTION CHANGE -> UNDERPLAYED CALLBACK` where relevant.
- Direction responsiveness is a casting criterion.
- Pair chemistry must survive underplaying; forced flirt performance is failure, not proof of chemistry.
- Provisional pilot lock and season lock are different gates.
- Long-form fatigue/listenability must be tested before season lock.
- Finalists must survive headphones / mono / phone translation.

## Audio comprehension / evidence
- One-listen causal comprehension is stronger than word-by-word intelligibility for evidence-heavy material.
- Listener must distinguish source objects, knowledge ownership and what each object actually proves.
- Repeated evidence playback must reuse/excerpt the same canonical source asset rather than regenerating identical words independently.
- Source changes should be physically audible without explanatory narration.
- Foley may be story-critical evidence of presence, absence, location, time or action; do not treat all Foley as decoration.
- Mono fallback must preserve causal distinction by level/depth/timbre, not pan alone.
- Use silence as cognitive reset where meaning changes.
- Music must not supply a moral verdict or reveal meaning before the evidence lands.
- Repair order for comprehension failure: performance/listening -> pause/spacing -> source identity -> mix focus -> edit/replay structure -> only then escalate a demonstrated text defect.

## Production / scale
- Run the smallest decisive pilot before scaling expensive generation.
- `DRY RUN != LIVE EVIDENCE`.
- Provider/API output never becomes canon merely because it rendered successfully.
- Edit-first before regeneration when performance is already correct.
- Real human listener evidence outranks internal scores for release validation.

---

# 10. WRITE-THROUGH LAW

A material accepted improvement may not remain only in one conversation.

For a universal improvement, update the smallest sufficient set:

`EVIDENCE / FINDING`
→ `INTEGRATION DECISION`
→ `UNIVERSAL PROTOCOL OR DOMAIN CANON`
→ `CONFIG / ROUTER`
→ `PROMPT SUPPLEMENT`
→ `RUNBOOK / EXECUTION CONTRACT`
→ `LEARNING/SYNC LEDGER`
→ `VERIFY PERSISTENCE`.

For project-only improvements, update project authority/status/handoff; do not pollute universal canon.

GitHub remains canonical machine-readable production state where the current workflow uses GitHub. Drive remains working/human-readable mirror/library state. Do not claim synchronization until readback/verification succeeds.

---

# 11. CONTINUATION WITHOUT MANUAL RESTATEMENT

For any substantive IVDIVO request:

1. identify active project from current message + recoverable persisted context;
2. restore current authority;
3. run bounded delta sync;
4. identify last completed artifact/open gates/blocker;
5. execute highest unblocked obligation;
6. persist material result and next state where the workflow requires persistence.

`и / дальше / продолжай / делай / работай` remains a zero-ambiguity command to continue the exact frontier, but it is no longer required merely to make the system remember its own persisted work.

If the Founder clearly starts a different project or asks a general question, route accordingly rather than blindly continuing an old project.

Persist a machine-readable sync state with at least:

- `last_sync_at`
- `scope`
- `active_project`
- `github_main_or_authority_sha`
- `drive_authority_ids`
- `prompt_authority_ids`
- `new_delta_clusters[]`
- `accepted_universal_mechanisms[]`
- `project_only_changes[]`
- `held_for_test[]`
- `rejected_or_duplicate[]`
- `invalidated_artifacts[]`
- `last_completed_artifact`
- `open_gates[]`
- `highest_unblocked_next_obligation`
- `provenance[]`

The state is a router aid, not higher authority than canon.

---

# 13. END CONDITION

A synchronization pass is complete when:
- material new deltas are classified;
- accepted universal mechanisms are recorded once;
- project-only facts remain isolated;
- affected routers/prompts are updated;
- stale duplicates are marked/suppressed;
- next work is recoverable without asking the Founder to reconstruct the previous conversation.

**NO SILENT CANON CHANGES. NO MODEL-VOTE CANON. NO DUPLICATE EVIDENCE INFLATION. CONTINUE FROM VERIFIED STATE.**
