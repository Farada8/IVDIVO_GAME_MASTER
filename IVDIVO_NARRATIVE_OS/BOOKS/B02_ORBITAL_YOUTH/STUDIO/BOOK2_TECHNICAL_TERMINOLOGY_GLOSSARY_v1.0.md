# IVDIVO — BOOK 2 ORBITAL YOUTH
# TECHNICAL TERMINOLOGY GLOSSARY v1.0

**Date:** 2026-08-17  
**Status:** ACTIVE GLOBAL-CONTINUITY AID / NOT IN-UNIVERSE EXPOSITION  
**Purpose:** keep Book Two technical language internally consistent during continuous read and global line pass.

This file defines **writer-room usage**, not what every character must say verbatim. Dialogue may simplify according to speaker knowledge. Narrative must not silently collapse distinct concepts.

## 1. FIXED DISPLAY TIMESTAMP

**Writer-room meaning:** the time shown by the ordinary/fixed system display for a state transition or clearance indication.

**Important:** after Ch26, this is **not** the universal alignment center for the mechanism.

**Do not equate with:**
- complete physical recovery;
- actual shared-loop state entry;
- universal truth timing.

## 2. FORMAL CONTROLLER CLOSURE / CLEAR INDICATION

**Meaning:** the controller has completed its defined logical/command transition and the ordinary system considers that transition formally closed/clear under its existing model.

**Important:** formal closure may occur while physical return/recovery is still settling.

**Do not write:** `controller says safe, therefore physical system safe`.

## 3. PHYSICAL RETURN / RECOVERY STATE

**Meaning:** the actual physical/system recovery after a transition — the underlying return toward a stable/conservative state.

This is not necessarily identical to what the formal controller/display indicates.

**Preferred generic wording:** `physical recovery`, `return state`, `recovery state` according to POV/context.

## 4. RESIDUAL RECOVERY / RESIDUAL RETURN

**Meaning:** a condition in which formal closure has occurred but the physical return has not fully settled to the conservative baseline relevant for the next transition.

This is the key late-book operational variable.

**Do not imply:** any residual recovery automatically causes danger.

## 5. SHARED-LOOP STATE / SHARED-LOOP STATE ENTRY

**Meaning:** a bounded relationship in which multiple transition/service paths share enough of a return/recovery structure that the order/timing of the next operation can matter while residual recovery remains.

Ch26–27 establish that such a state relationship can be inferred/reproduced under bounded conditions.

**Do not equate with:**
- dangerous oscillation itself;
- universal root cause;
- resident sensation.

## 6. ESTIMATED SHARED-LOOP STATE-ENTRY WINDOW

**Meaning:** the inferred time/state window in which the control-state relationships indicate entry into the candidate shared-loop condition.

It is inferred from control/physical-state relationships, **not** centered on resident/support timing.

## 7. TRANSITION OVERLAP

**Meaning:** descriptive/predictive overlap among return/recovery and subsequent service/control transitions.

Earlier in the book it is a predictor/candidate relation, not a proven cause.

Use carefully so later `residual-recovery/shared-loop state` feels like a refinement, not a new unrelated concept.

## 8. DANGEROUS OSCILLATION / INSTABILITY FAMILY

**Meaning:** the dangerous live behavior associated with the Ch20 class of failure and the contained late Ch35 event family.

**Important:** Ch27 controlled reproduction does **not** reproduce the dangerous oscillation itself. It reproduces the candidate state relationship that can precede/enable a dangerous condition under some configurations.

**Do not write:** `shared-loop state = oscillation`.

## 9. LEGACY / FIXED AUTOMATIC THRESHOLD

**Meaning:** the existing automatic system's safety/isolation threshold under the old control logic.

In Ch34–35, this remains active and unchanged.

R3-S may become legitimately actionable **before** this threshold is crossed because it uses a separately reviewed predictive envelope.

**Do not imply:** legacy system is stupid/useless. It is later and less selective for this specific bounded event class.

## 10. SHADOW ESTIMATOR

**Meaning:** the not-yet-automatic state-aware analytical layer used to estimate whether the local transition sequence is entering/remaining in the bounded residual/shared-loop condition.

**Status:** enough evidence for human-confirmed contingency under exact conditions; not enough validation for autonomous control authority.

## 11. R3-S / LOCAL SAFE-STATE — SEGMENT THREE

**Meaning:** the temporary, adult-authorized, local fail-safe contingency used during reduced redundancy.

**Trigger basis:** operational envelope, not human reports.

**Action:**
- close Segment Three inbound resident/service gate;
- hold next defined local service transition;
- force local shared service chain toward already validated conservative recovery;
- hand wider action to adult operations.

**Cannot:**
- reopen;
- tune controller;
- change thresholds;
- route ring-wide;
- alter other segments;
- decide housing.

## 12. R3-S SHADOW — WATCH / PARTIAL MATCH / MATCH

**WATCH:** relevant conditions approaching but full envelope not met.

**PARTIAL MATCH:** some but not all pre-registered operational conditions satisfied.

**MATCH:** full bounded operational envelope satisfied; R3-S becomes available to authorized operators.

**Important:** `MATCH` does not mean legacy automatic threshold crossed or dangerous oscillation already confirmed.

## 13. CONSERVATIVE RECOVERY STATE / SAFE-STATE OPERATIONS

**Meaning:** intentionally slower/more restrictive local operating condition that preserves greater recovery margin.

After Ch35, Segment Three can remain occupied under conservative safe-state support while normal inbound/transition operation is suspended/revalidated.

Later inbound may resume under a corrected conservative procedure without implying normal full commissioning.

## 14. SEGMENT PROFILE / CERTIFIED FLOOR

**Segment profile:** the bounded combination of occupancy, route, service timing, environmental and control restrictions under which a specific Ring Six segment is currently defensible.

**Certified floor:** the minimum accepted safety/recovery margin under that approved profile.

**Do not equate with:** full-ring certification.

## 15. NORMAL COMMISSIONING

**Meaning:** intended normal operating profile of Ring Six, not merely the fact that people are living in some safe segments.

By Ch35–36:
- **occupation can be active**;
- **normal full commissioning can remain incomplete**.

This distinction is part of the book's resolution.

## 16. RESIDENT / SUPPORT REPORT

**Meaning:** a person's reported sensation, interface observation or support event associated with a transition.

**Evidence status:**
- may be temporally useful;
- may prompt review;
- may corroborate another evidence rail;
- can be absent in otherwise relevant events;
- is neither infallible nor automatically causal.

**Do not write as fact:** `the body knew first` unless a POV character is expressing an interpretation, not narrator truth.

## 17. NEGATIVE / NO-REPORT CASE

**Meaning:** an event within a relevant candidate condition where the expected report/effect is absent, or a control sequence that does not reproduce the candidate result.

Negative cases are essential evidence, not noise to be explained away.

Use enough to preserve scientific/epistemic discipline; do not repeatedly lecture methodology.

## 18. EVENT-ORDER DATA

**Meaning:** de-identified ordering/timing relation among events without carrying identity, raw personal-interface values, medical/accommodation detail or source text.

This is the kind of bounded information that can move through review without violating established privacy boundaries.

## 19. REVIEW HOLD

**Meaning:** Ollie's unrestricted commissioning access is suspended/restricted after the failure sequence.

Later roles do not silently erase it.

Possible later permissions are narrower overlays:
- de-identified model support;
- adult-owned test participation;
- read-only migration watch;
- exact local fail-safe secondary authority;
- bounded post-climax redesign/review contributor.

**Do not write:** a new role as equivalent to full restored access unless canon explicitly changes.

## 20. TECHNICAL ROOT CAUSE — CURRENT CEILING

Book Two does **not** prove one universal root cause for every Ring Six anomaly/configuration.

What it establishes strongly enough for story resolution:
- formal controller clearance can precede relevant physical recovery;
- live sequence/load relations can matter during residual recovery;
- a bounded shared-loop/residual state relationship can be reproduced;
- conservative operating rules and segmentation can support real habitation;
- a human-confirmed predictive contingency can justify earlier local isolation for at least the Ch35 event class;
- later legacy evidence validates that event-specific early action.

That is an **operational solution with bounded mechanism knowledge**, not incomplete writing by itself.

## GLOBAL LINE-PASS RULE

When a term appears, ask:
1. Is this new information?
2. Is the exact term necessary for the POV/decision?
3. Has the reader already learned the distinction?
4. Can the scene show it through a light, gate, delay, held cart, permission state or consequence instead?

Technical consistency is mandatory. Technical repetition is not.
