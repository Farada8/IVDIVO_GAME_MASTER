# 18E — SELF-IMPROVEMENT IDENTITY / FRESHNESS / EVIDENCE INTEGRITY PROTOCOL v1.0

**Status:** CANDIDATE PROTOCOL / POST-v11.2 EXTENSION / NOT NEW TOP-LEVEL OS  
**Date:** 2026-08-21

## Purpose

Extend the existing Self-Improvement Meta Engine v2 with three proof-bearing gates exposed by parallel production:

1. **Global Candidate Identity Gate** — one global `SI-xxxx` cannot name two different mechanisms.
2. **Authority Freshness + Version-Chain Gate** — durable state must be revalidated against live provider authority before continuation.
3. **Evidence-Class Claim Gate** — evidence of one class cannot silently satisfy a claim requiring another.

This protocol does not replace Self-Improvement v2, Cross-Conversation Autopilot, Session Resilience, project state, story canon, Human Signal, provider adapters or Founder authority.

## Gate ordering

Before a candidate or project mutation:

1. **BLOCKER / SAFETY / FOUNDER gate**
2. **Candidate identity**
3. **Authority/state freshness**
4. **Version-chain consistency**
5. **Dependency/readiness**
6. **Evidence-class requirements**
7. **Mutation transaction**
8. **Readback**
9. **Regression**
10. **Promotion review**

A later gate cannot override an earlier failure.

## Candidate identity law

Full-family visibility precedes ID allocation. Base registry, all extension shards and active pending candidates are one namespace. Historical redirect/tombstone records preserve provenance but are not active candidates.

True semantic collision blocks compaction/promotion. Exact tracked migration debt may allow unrelated reversible engineering, but `promotion_eligible=false` until repaired and read back.

## Freshness law

A provider revision change creates `STALE_REBASE_REQUIRED`, not a canon decision. Semantic re-read is mandatory. Unknown provider state creates `REVIEW_REQUIRED`, not PASS.

## Evidence law

Evidence classes are orthogonal. The system must store the class required by a claim before accepting the claim. Model agreement, report count and transformed copies do not manufacture independent provenance families.

## Self-Improvement write-through

New mechanisms enter the existing lifecycle as candidates. This protocol itself cannot promote its own components from deterministic fixtures.

Candidate promotion requires the controlling contract, including real production or human/provider evidence where specified.

## Stop conditions

STOP or HOLD when:
- untracked candidate-ID collision exists;
- live authority cannot be observed but the action depends on it;
- authority chain has two CURRENTs/cycle/rank regression;
- required evidence class is absent;
- provider/human/specialist/market evidence would have to be fabricated;
- parallel branch owns the same repair and has fresher compatible work;
- a mutation would overwrite newer main/Drive state.

## Success condition

- real repository identity scan is clean or contains only exact tracked migration debt;
- collision migrations preserve semantic evidence and redirects;
- freshness detects both unchanged and changed real provider revisions without canon inflation;
- evidence-class negative tests remain fail-closed;
- at least two independent project families exercise freshness/evidence gates;
- GitHub + Drive persistence/readback succeeds;
- Self-Improvement promotion remains evidence-gated rather than test-count-gated.
