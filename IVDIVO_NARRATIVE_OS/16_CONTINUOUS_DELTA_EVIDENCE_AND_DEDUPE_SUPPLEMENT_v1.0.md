**Status:** PROPOSED CURRENT UPGRADE  
**Date:** 2026-08-21  
**Parent:** `13_CONTINUOUS_MULTI_MODEL_STUDIO_PROTOCOL_v1.0.md`

This supplement adds evidence hygiene and write-through rules discovered during cross-dialog synchronization.

## 1. EXTENDED DELTA CLASSIFICATION

Material deltas may be classified:
`PROJECT_CANON_CHANGE / STATUS_FRONTIER_UPDATE / UNIVERSAL_MECHANISM_CANDIDATE / PROMPT_PROGRAM_UPGRADE / EXECUTION_TOOLING_UPGRADE / EXTERNAL_EVIDENCE / REFERENCE_LEARNING / DUPLICATE / SUPERSEDED / REJECTED`.

Disposition:
`ADOPT_PROJECT / UNIVERSALIZE / ACCEPT_WITH_MODIFICATION / HOLD_FOR_TEST / REJECT / SUPERSEDE`.

File existence, newer-looking filename or model confidence is not proof of validity.

## 2. SEMANTIC DEDUPE / ANTI-ECHO LAW

The same claim repeated in several chats, summaries, mirrors, duplicate books or different models does not gain evidentiary weight merely through repetition.

Group materially equivalent findings under a `delta_cluster_id` and preserve strongest primary provenance.

Duplicate source copies add zero independent evidence weight.

Two models making the same unsupported guess is not triangulation.

## 3. CROSS-MODEL SOURCE-PARITY LAW

When a cross-model comparison claims independent confirmation:
1. verify each reviewer used the same current source/version where parity matters;
2. inventory what actually exists before judging it;
3. require source evidence for existence claims;
4. keep orthogonal reviewer roles independent where independence is the point;
5. never decide by model vote;
6. evaluate defect diagnosis separately from proposed rewrite;
7. classify each recommendation before authority mutation.

Missing external review = `UNKNOWN / NOT_RECEIVED`.

## 4. UNIVERSALIZATION FIREWALL

Only abstract process/craft mechanisms cross projects by default.

Never transfer without explicit authority: names, provider voice IDs, culprit/solution, distinctive clue chains, chronology, signature motifs/melodies, unique scene order, project relationship state, obsolete branch facts or proprietary expression.

`PROJECT RESULT -> ABSTRACT MECHANISM -> REMOVE DISTINCTIVE CONTENT -> TEST GENERALITY -> UNIVERSAL RECORD -> REBIND THROUGH ACTIVE PROJECT AUTHORITY`.

## 5. SELECTIVE INVALIDATION

A new rule does not reopen all downstream work.

Repair the earliest demonstrated failing layer and invalidate only true descendants. Preserve unaffected sibling hashes/locks and unrelated project canon.

## 6. WRITE-THROUGH LAW

A material accepted improvement may not remain only in chat.

Universal change:
`EVIDENCE -> INTEGRATION DECISION -> UNIVERSAL/DOMAIN PROTOCOL -> CONFIG/ROUTER -> PROMPT/EXECUTION CONTRACT IF AFFECTED -> SYNC/LEARNING STATE -> READBACK VERIFY`.

Project-only change updates project authority/status/handoff only.

## 7. LEARNING PROMOTION TEST

Promote only if the finding plausibly improves a reusable production decision: causality, character specificity, comprehension, source provenance, relationship truth, originality, execution safety, cost control, QC or release confidence.

Novelty or elegance alone is insufficient.

**NO DUPLICATE EVIDENCE INFLATION. NO MODEL-VOTE CANON.**
