# IVDIVO — CONTINUOUS DELTA + LEARNING REGISTRY

## PURPOSE

Autopilot restores the current project and continues work. This supplement adds the missing second half: **discover and integrate material improvements created elsewhere without asking the Founder to remember which dialogue created them.**

Any substantive IVDIVO request may trigger a bounded delta scan when newer persisted work could materially change the answer. `и / дальше` remains shorthand, not a heartbeat.

## DELTA SOURCES

Check only relevant surfaces:
1. newest Founder instruction and active project state;
2. GitHub `main` deltas since the last verified sync;
3. current Drive authority/frontier/prompt indexes and recent project authorities;
4. Project/session handoffs and Multi-Model Memory;
5. Story Engine / Source Passports / Mechanism Bank / Library changes;
6. actual Claude/Grok/other-model outputs;
7. actual specialist/human/listener/market evidence;
8. domain Learning Registry results from finished/pilot work.

Unavailable source = `UNKNOWN / NOT_RECEIVED`, never reconstructed from confidence.

## CLASSIFICATION

Every material delta receives one class:
- `PROJECT_CANON_CHANGE`
- `STATUS_FRONTIER_UPDATE`
- `UNIVERSAL_MECHANISM_CANDIDATE`
- `PROMPT_PROGRAM_UPGRADE`
- `EXECUTION_TOOLING_UPGRADE`
- `EXTERNAL_EVIDENCE`
- `REFERENCE_LEARNING`
- `DUPLICATE`
- `SUPERSEDED`
- `REJECTED`

Then one disposition:
`ADOPT_PROJECT / UNIVERSALIZE / ACCEPT_WITH_MODIFICATION / HOLD_FOR_TEST / REJECT / SUPERSEDE`.

## ANTI-ECHO / SEMANTIC DEDUPE

The same claim repeated in chats, summaries, mirrors or multiple models does not gain evidence weight merely through repetition.

Group equivalent findings under a `delta_cluster_id`. Preserve provenance and strongest primary evidence. Duplicate files/books do not add independent weight.

Two models making the same unsupported guess is not triangulation.

## CROSS-MODEL PARITY LAW

For comparisons that claim independent confirmation:
- give reviewers the same current source when source parity matters;
- inventory what actually exists before evaluating it;
- require source evidence for existence claims;
- use orthogonal reviewer roles where useful;
- never decide by model vote;
- evaluate defect diagnosis separately from proposed rewrite;
- classify every recommendation `ACCEPT / ACCEPT_WITH_MODIFICATION / HOLD_FOR_TEST / REJECT` before changing authority.

Useful orthogonal roles: development/causal Red Team; cold reader/listener/comprehension; strongest innocent/prosecution-vs-defence; anti-generated-dialogue; market/retention; narrow domain specialist; real Human Signal.

## UNIVERSALIZATION FIREWALL

Transfer only abstract mechanisms/process improvements.

Never transfer without explicit authority: names, voice IDs, culprit/solution, distinctive clue chain, chronology, signature motif/melody, unique scene order, project relationship state, obsolete branch facts or proprietary expression.

Use:
`PROJECT RESULT -> ABSTRACT MECHANISM -> REMOVE DISTINCTIVE CONTENT -> TEST GENERALITY -> UNIVERSAL RECORD -> REBIND THROUGH ACTIVE PROJECT AUTHORITY`.

## SELECTIVE INVALIDATION

A new universal rule does not automatically reopen old locked work.

Repair the earliest demonstrated failed layer and invalidate only true descendants. Preserve unrelated character fingerprints, scenes, locks and hashes.

Human/external feedback enters a patch queue first; it never silently regenerates story.

## WRITE-THROUGH LAW

A material accepted improvement may not remain only in chat.

Universal improvement:
`EVIDENCE -> INTEGRATION DECISION -> UNIVERSAL/DOMAIN PROTOCOL -> CONFIG/ROUTER -> PROMPT SUPPLEMENT -> EXECUTION/RUNBOOK if affected -> SYNC/LEARNING STATE -> READBACK VERIFY`.

Project-only improvement:
update project authority/status/handoff only; do not pollute universal canon.

## LEARNING PROMOTION TEST

Promote a project result only if it plausibly improves a reusable decision such as causality, character specificity, comprehension, source provenance, relationship truth, execution safety, cost control, QC or originality.

Elegance, novelty or model enthusiasm alone are insufficient.

## CONTINUATION CONTRACT

For any substantive IVDIVO request:
1. restore verified current state;
2. scan bounded relevant deltas;
3. integrate accepted improvements;
4. recompute open gates/dependency DAG;
5. execute the highest unblocked obligation;
6. continue through further executable descendants;
7. persist `DONE / STATUS / NEXT`.

Do not make the Founder reconstruct prior work that persisted sources can recover.
Do not claim background/asynchronous progress when no task/session is running.

## MINIMUM SYNC STATE

Persist where useful:
`last_sync_at, scope, active_project, github_authority_sha, drive_authority_ids, prompt_authority_ids, delta_clusters, accepted_universal_mechanisms, project_only_changes, held_for_test, duplicates_rejected, invalidated_artifacts, last_completed_artifact, open_gates, highest_unblocked_next_obligation, provenance`.

The registry is routing state, never higher authority than canon.

**CONTINUE FROM VERIFIED STATE. NO SILENT CANON CHANGE. NO MODEL-VOTE CANON. NO DUPLICATE EVIDENCE INFLATION.**
