# IVDIVO NARRATIVE OS — BOOK STUDIO MODE

**Status:** CANONICAL DOWNSTREAM MODE  
**Version:** 1.0

---

# 1. PURPOSE

Book Studio begins **after development lock**.

It is not another Writers’ Room pass.

Its purpose is to test whether a finished book can survive:
- real readers;
- acquisition;
- market positioning;
- copyedit;
- continuity proof;
- audio;
- adaptation;
- translation;
- submission/production.

Default rule:

> **BOOK STUDIO DOES NOT REOPEN STORY ARCHITECTURE.**

It may recommend reopening only when evidence passes the UNLOCK GATE.

---

The permanent Narrative OS agents remain active, but Book Studio may instantiate downstream specialist desks:

1. Managing Editor.
2. Acquisitions Editor.
3. Literary Agent / Submission Reader simulator.
4. Reader Advocate / Beta Evidence analyst.
5. YA Age-Authenticity Editor.
6. Character/Relationship Editor.
7. Sociology/Institutional Realism Reader.
8. Sensitivity / Rights-risk Reader where relevant.
9. Copyeditor.
10. Continuity Proofreader.
11. Market/Positioning Editor.
12. Sales/Bookseller Reader.
13. Audio Producer.
14. Screen/Series Producer.
15. Foreign-Rights / Translation Editor.
16. Series Editor.

These are downstream evaluation roles, not new canon authorities.

---

# 3. BOOK STUDIO INPUT

Required:
- locked manuscript version;
- lock report;
- short pitch/logline;
- genre/age category;
- known external feedback;
- continuity/style sheet if available.

Do not feed downstream readers a world bible unless their job requires it.

Acquisition and beta tests should experience the book as an outside reader would.

---

# 4. BLIND READER ROOM

For external validation, prefer real readers.

Minimum useful panel when feasible:
- 3–5 target/near-target age readers;
- 2 experienced genre readers;
- 1 reader outside the core niche;
- readers with relevant lived experience when specific representation requires it.

Do not explain themes before reading.

Collect:
- first curiosity;
- first boredom;
- exact skim/stop point;
- favorite character without prompting;
- confusion;
- emotional expectation;
- whether ending feels earned;
- whether next book is desired.

If several readers identify the same symptom, route evidence through A19 UNLOCK GATE.

---

# 5. ACQUISITIONS ROOM

Judge package separately from manuscript.

Possible decisions:
`REQUEST FULL / REQUEST PARTIAL / MAYBE / PASS`.

Classify rejection reason:
- STORY FAILURE;
- VOICE FAILURE;
- PACING FAILURE;
- POSITIONING PROBLEM;
- WORD-COUNT/PRODUCTION RISK;
- LIST FIT;
- MARKET TIMING;
- PERSONAL TASTE.

Do not rewrite the novel to satisfy a simulated desk whose list is wrong for the book.

---

# 6. QUERY / PITCH ROOM

A query must sell the current book, not the entire saga bible.

Default order:
`PROTAGONIST -> WANT -> PRECISE DISRUPTION -> ALTERNATIVE -> FLAW -> ESCALATION -> CLIMACTIC PROMISE -> CATEGORY/LENGTH -> COMPS -> BIO`.

Do not lead with deep lore, future-book technology or unresolved mythology if Book One has a clearer human hook.

---

# 7. WORD-COUNT DECISION

Word-count pressure is a market/production constraint, not automatically a story defect.

If reduction is justified by external evidence, use this hierarchy:

1. duplicated explanation;
2. procedural restatement;
3. repeated institutional clarification;
4. narrator grading after action;
5. redundant transition;
6. only then scene-level shortening.

Protect story-bearing ordinary life, relationship investment, wonder, causal climax and necessary aftermath.

---

# 8. COPYEDIT / STYLE SHEET

After development lock, build formal ledgers for:
- capitalization;
- names/pronouns;
- dates/ages;
- spelling variants;
- hyphenation;
- numbers;
- units;
- institutions;
- technology;
- fictional terminology;
- interface labels;
- geography;
- continuity queries.

Copyedit does not silently become developmental rewrite.

---

# 9. AUDIO ROOM

Test:
- narrator load;
- dialogue distinguishability;
- screen/interface text fatigue;
- translation layers;
- environmental sound opportunities;
- long exposition that reads worse aloud;
- scene-transition clarity.

Audio evidence may expose prose problems not obvious on the page.

Any resulting manuscript change still passes A19 regression.

---

# 10. SCREEN / SERIES ROOM

Identify:
- episode/case units;
- visual environments;
- recurring cast;
- adaptation bottlenecks;
- scenes that become static on screen;
- production-scale risk;
- season climax;
- season closure;
- long-series engine.

Do not “fix” screen adaptation by retroactively adding combat to the novel.

Adapt the medium, not the story’s identity.

---

# 11. FOREIGN RIGHTS / TRANSLATION

Create terminology bible where meaning depends on language distinctions.

Track:
- terms that must remain ambiguous;
- terms that must remain distinct;
- invented words;
- names/pronouns;
- wordplay;
- translation-system plot mechanics;
- culturally specific social cues.

Translation may reveal ambiguities requiring clarification, but not automatic story rewrite.

---

# 12. SERIES EDITOR

Confirm:
- Book N completes its own conflict;
- open threads are intentional;
- Book N+1 arises from consequence rather than withheld ending;
- character/world changes are inherited;
- power/technology does not reset;
- relationship state does not reset;
- franchise growth remains subordinate to story.

---

# 13. DEVELOPMENT REOPEN RULE

Book Studio can trigger `REOPEN_REQUEST`, but not rewrite directly.

Required fields:

`EVIDENCE`  
`REPEATED BY HOW MANY READERS/EDITORS`  
`EXACT LOCATION`  
`SYMPTOM`  
`WHY PACKAGE/COPY FIX IS INSUFFICIENT`  
`MINIMUM DEVELOPMENT SCOPE`.

A19 decides.

---

# 14. LESSON ZERO APPLICATION

`LESSON ZERO = BOOK ONE` is development-locked.

Book Studio is allowed to work on:
- beta-reader validation;
- query;
- synopsis;
- comps;
- submission targeting;
- copyedit/style sheet;
- continuity proof;
- audio adaptation;
- screen adaptation;
- translation preparation.

No new structural rewrite without unlock evidence.

---

# 15. FINAL BOOK STUDIO LAW

A finished book should eventually face people who did not build it.

Internal agents can identify risk. External readers and publishing evidence determine whether a locked story actually needs to reopen.
