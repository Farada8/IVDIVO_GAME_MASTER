# SYNTHESIS AND ROADMAP — N01–N32

## Executive conclusion
The second sprint materially changed the problem. The project no longer primarily lacks ideas for prompts; it lacks **safe promotion, runtime integration and real calibration** for a small set of reusable mechanisms.

The 32 prompts produced candidate implementation surfaces for boot authority, evidence-class discipline, Story Core causality, protagonist agency, adaptive opposition, character/social pressure, relationship authority, dialogue state, scene modularity and mystery evidence fairness.

Two prompts remain legitimately blocked: real transcript ingestion and its independent audit. They require a real exported/pasted conversation artifact; substituting a synthetic fixture would create false production evidence.

## Minimal initiative clusters

### A. P0 — Authority / registry integrity
1. Reconcile SI-0008 into the exact-current Improvement Registry.
2. Implement registry-reference invariant tests.
3. Promote a single boot manifest only after cold-start parity and stale-pointer tests.
4. Complete durable project-state coverage by recovering actual authorities, not extrapolating aggregate labels.

### B. P0/P1 — Evidence-class integrity
1. Introduce a shared evidence-aware gate contract.
2. Automate negative evidence-collapse fixtures.
3. Apply the same evidence firewall to writing, audio, transcript recovery, source research and market claims.

### C. P1 — Story causality stack
The Story Core contract, protagonist state-change ledger and opposition adaptation ledger form one stack:
`WHY NOW -> WANT -> ACTION/TACTIC -> RESPONSE/COUNTER -> PRICE -> ADAPTATION -> MIDPOINT TRANSFORMATION -> CLIMAX CHOICE -> RESOLUTION`.
Do not promote them as three competing engines. Integrate as conditional diagnostics under existing Story Engine authority.

### D. P1 — Character / social / relationship stack
Behavioral contradiction, Social Reality Pressure, Relationship Authority Graph and Pair-State Dialogue Card belong together. They should share current-state/authority semantics rather than become four isolated forms.

### E. P1 — Scene / evidence stack
Scene delete/swap tests and Universal Evidence Ledger are architecture/continuity diagnostics. They should feed the existing Red Team/Story Gate and mystery fairness layers, not become a new parallel Narrative OS.

### F. P2 — Real transcript recovery pilot
The code/protocol is runtime-verified, but production evidence remains open. Next progress must use a real large exported/pasted conversation, then independent audit, then package the extension into a future tested engine ZIP.

### G. P3/P4 — Multi-AI benchmark and concurrency
Fixed fixtures now exist. Next value comes from running genuinely independent model/backend evaluations and stale-write/concurrency tests, not writing more handoff prose.

## Promotion order

## Anti-bloat decisions
- Do not create a new Story Engine.
- Do not create a second Self-Improvement authority.
- Do not create a second project-state system.
- Do not universalize P53 romance behavior.
- Do not convert internal model validation into Human Signal.
- Do not create more schemas unless a live pilot demonstrates a field/contract gap.
- Do not auto-run all follow-up prompts when a real pilot is more informative.

- N11/N12 require real transcript input.
- N16/N28 require independent blind reviewers for genuine blind evidence.
- Candidate schemas are not CURRENT until applied, tested, reconciled and read back.
- D09 still requires Founder approval/lock and is not touched by this sprint.

## Stop rule
After any pilot, stop or prune if:
- current authority already solves the defect;
- no new evidence changes the decision;
- mechanism duplicates another current contract;
- false-positive/overhead cost exceeds defect reduction;
- a real manuscript/audio pilot is more informative than another prompt;
- active production priority is higher.
