# 32 PROMPTS — SEQUENTIAL R&D / PRODUCTION AUDIT

**Execution order is binding for this sprint.** Each prompt may use results from earlier prompts but may not silently change story canon.

## P01 — Authority / Frontier Rebase
Restore the freshest IVDIVO authority and production state from GitHub main, Drive current pointers and project-specific state. Identify the current system schema, Self-Improvement state, active portfolio gate, and any material concurrent-dialog advances. Do not trust chat memory or stale Drive labels. Return CURRENT / SUPERSEDED / OPEN GATE / NEXT SAFE ACTION.

## P02 — Boot-Path Contradiction Scan
Trace the exact new-chat boot chain from START HERE through Prompt Authority Index, CURRENT_PROMPTS, CURRENT_WORKSTATE, prompt router, project authority and machine state. Detect version-label mismatches, obsolete 'current' claims, loops, dead references and routes that could regress a project. Propose the smallest compatibility fix; do not create a new universal router unless no current file can absorb the repair.

## P03 — Durable Project-State Coverage Audit
Audit whether every active or text-complete IVDIVO book/commercial drama has a durable machine-readable project-state pointer comparable to D04 and D09. Distinguish detailed canon from routing state. Identify projects that can still force a future model to reconstruct status from chat/Drive timestamps. Produce a priority list for missing PROJECT_STATES coverage.

## P04 — Self-Improvement Registry Integrity
Cross-check CURRENT_IVDIVO_SELF_IMPROVEMENT_STATE against 31_IDEAS/CURRENT_IMPROVEMENT_REGISTRY. Verify every referenced SI candidate exists, has provenance, owner, next action, next gate, application targets and required terminal reason/evidence. Flag state/registry drift as an integrity defect, not a cosmetic issue.

## P05 — Prompt / Router Sprawl and Dedupe
Inventory the current universal and genre prompt/router layers by function rather than filename. Find duplicate responsibilities, compatibility maps still presented as primary authority, repeated startup text, and programs that fire merely because they exist. Recommend consolidation by smallest sufficient router, keeping history without routing through it.

## P06 — Evidence-Class Firewall Audit
Test the system against evidence-category collapse: automated tests vs literary quality, AI review vs Human Signal, dry run vs live provider evidence, source inspection vs runtime execution, prediction vs market behavior, clue vs interpretation, and chat transcript vs authority. Identify any prompt or state wording that still permits false PASS or premature promotion.

## P07 — Transcript Recovery Operational Readiness
Audit the verified transcript-recovery extension as a production mechanism. Separate deterministic extraction, semantic reconciliation, persisted-claim verification, canon decisions and ingestion-complete status. Identify the first real operational evidence still missing and the exact acceptance gate for a large pasted/exported transcript.

## P08 — Multi-AI Parallelism / Handoff Parity
Stress-test GPT/Claude/Grok/other-model collaboration under one shared state. Verify bounded RUN CARD inputs, same-source parity for comparisons, diagnosis/fix separation, independence of parallel branches, disposition of recommendations and persistence. Identify where model agreement could still be mistaken for independent evidence or where two agents could mutate the same frontier.

## P09 — Story Core Gate Robustness
Audit the universal Story Core gate before prose: HERO / WANT / WHY NOW / OPPOSITION / WRONG STRATEGY / PRICE / MIDPOINT / CLIMAX CHOICE / RESOLUTION / SERIES HOOK. Determine whether current prompts can accidentally proceed with missing causality because fields are filled but not causally linked. Propose a causal acceptance test that cannot be satisfied by labels alone.

## P10 — Protagonist Agency Without Aggression
Apply the current action/adaptation law to the writing system. Verify that agency is measured as consequential pursuit/refusal/testing/cooperation/restraint/bargaining/withdrawal/protection/exposure/endurance, not loud confrontation. Design a diagnostic for protagonist-caused state change and detect any old prompt that equates activity with aggression or screen time.

## P11 — Opposition Adaptation / Escalation Engine
Audit whether opposition changes strategy in response to protagonist action, or merely increases stakes on schedule. Build an opponent-adaptation ledger: observed protagonist move -> opponent inference -> counter-move -> new constraint -> protagonist adaptation -> price. Test its usefulness for novels, mysteries, romance and serial drama.

## P12 — Character Psychology / Contradiction System
Audit character design for goal, private desire, fear, contradiction, ordinary life, competence, mistake, relationship, price and change. Separate private character laboratory from manuscript exposition. Add a behavior-based contradiction test: the contradiction must produce choices under pressure, not merely two adjectives in a bible.

## P13 — Sociology / Institutional Reality Gate
Evaluate how consistently the studio models class, money, housing, work, bureaucracy, family, status, institutions, community norms and power. Identify genres/projects where psychology is strong but social reality is thin. Design a sociology gate that changes plot pressure without becoming exposition or policy dialogue.

## P14 — Relationship / Consent / Power Authority Graph
Audit romantic and non-romantic relationship tracking. Require independent wants, trust, boundary, vulnerability, power asymmetry, rupture, repair, choice and current-line consent where relevant. Design an ensemble Relationship Authority Graph that prevents erased intimacy, rescue, wealth, employment power or privileged knowledge from becoming emotional debt.

## P15 — Dialogue as Action / Voice Differentiation
Audit P51/P52/P53 and dialogue laws against actual dramatic function. Ensure every important conversation has objective, resistance, tactic, status, listening, subtext, interruption/withholding and a turn. Treat blind attribution and fingerprints as diagnostics, not proof. Identify the minimum pair-specific data needed before rewriting dialogue.

## P16 — Scene Admission / Deletion / Swap Test
Strengthen the scene law WHO WANTS WHAT / WHY NOW / WHAT STOPS THEM / WHAT CHANGES with admission tests. For every scene ask what causal bridge breaks if deleted and whether two adjacent scenes can swap without consequence. If deletion or swapping is possible, diagnose whether the defect is causality, escalation, relationship state or evidence order.

## P17 — Mystery / Evidence Fairness Schema
Turn the evidence law into a reusable mystery ledger: world fact, trace/source, lineage, access, reliability, surface meaning, true meaning, alternative model, corroboration, current-line availability, action and payoff. Ensure solution proof never depends on unavailable evidence or memory-only knowledge. Define a machine-readable schema candidate without importing project-specific clue content.

## P18 — Suspense / Waiting-Question Decay
Audit the Waiting-Question Ledger for retention. Add question age, last meaningful update, delay source, escalation, transformation, stale risk and payoff type. Detect serials that keep questions open without changing them, repeat cliffhanger types, or substitute confusion for suspense. Produce a rule for retiring or transforming stale questions.

## P19 — World Reveal Through Action
Audit worldbuilding prompts so observable phenomenon and ordinary life precede terminology. Use ordinary objective -> system constraint -> consequence -> choice -> new evidence/relationship/status. Detect lore dumps, ontology-first explanations and settings that do not materially change work, adolescence, money, family, transport or law.

## P20 — Youth / Orbital Civilization Authenticity
Audit youth-facing material against the Youth Law: friends, attraction, jealousy, embarrassment, family, school/work, money, hobbies, sport, parties, status, boredom, exclusion, independence and bad decisions. For orbital settings, test whether habitat economics, transport, maintenance, AI/synthetic bodies and nonhuman neighbours actually change adolescence rather than decorating an Earth school story.

## P21 — Melodrama / Dorama Emotional Engine
Audit mass-market romance/melodrama programs for emotional legibility without inflation. Check Project Romance Weight, anticipation, micro-care, vulnerability, rupture/repair, social danger, ordinary life and meaningful choice. Detect repetitive suffering, forced misunderstandings, billionaire/rescue shortcuts and constant temperature-5 melodrama.

## P22 — Prose Rhythm / Anti-Generated-Text
Use the anti-choppiness route to diagnose prose before line cosmetics. Separate inner process speed, outer motion speed, sentence length and paragraphing. Detect repeated generated-text patterns, symmetrical dialogue, abstract realization followed by moral explanation, stock gestures and tiny-paragraph intensity. Repair only after scene/causal function passes.

## P23 — Climax / Resolution / Series-Hook Gate
Audit final-act architecture. The climax must require the protagonist's choice, pay accumulated price and close the book's main conflict. Verify irreversible consequence, ordinary-life aftershock and changed relationship/world state. Permit a series hook only after resolution; reject finales that merely advertise the next book or convert aftermath into exposition.

## P24 — Reference Intelligence Strict-Lifecycle Triage
Use the strict source lifecycle and current 31/40 checkpoint. Do not reread the whole library. Identify which unsynthesized/integrity-blocked sources could materially change current Story/Character/Dialogue/Audio decisions, and which should remain untouched until a real problem requires them. Produce a problem-targeted retrieval queue and stop rule.

## P25 — Originality / Source-Distance Red Team
Stress-test the REFERENCE -> ABSTRACT MECHANISM -> TRANSFORM -> ORIGINAL APPLICATION law. Look beyond wording: compare plot sequence, scene function order, unique character configuration, signature invention, clue chain, setting mechanism and distinctive dialogue. Define a source-distance challenge that can reject an over-close derivative even when prose is paraphrased.

## P26 — Market / Audience Promise Without Fake Validation
Audit market and audience reasoning. Separate acquisition/packaging, episode/chapter retention, satisfaction/finale and real behavior. Ensure title/description/key art/first minute promise the story actually delivered. Ban 'market validated' claims without real data and define what internal market-reader analysis may legitimately decide.

## P27 — Locked Text -> Audio Adaptation Contract
Audit the handoff from locked story to audio production. Define what may change for hearability, performance and pacing without reopening story canon. Protect exact clue/relationship/story function, evidence order and source identity. Require an adaptation delta ledger for any non-trivial spoken-text change.

## P28 — Voice Casting / Performance Binding
Audit universal voice audition and binding. Require loudness-matched dry comparison, natural/restrained and directed-change takes, functional pressure states, role-specific hard fails, pair/ensemble chemistry where relevant, long-form fatigue, mono/phone/headphone translation and provisional vs season lock. Link character P51 fingerprints to performance goals without provider-specific canon.

## P29 — Sound / Music / One-Listen Comprehension
Audit sound dramaturgy as story information. Track source/object identity, acoustic domain, proximity, point-of-audition, protected silence, shared musical facts and listener inference. Design a one-listen blind comprehension test for evidence-heavy audio and route failures to performance/edit/mix before protected-text rewrite.

## P30 — Machine Execution / Package Regression
Audit the executable engine frontier and packaging. Distinguish source-verified extensions from what is actually inside the promoted ZIP. Verify machine schemas, continuation fail-closed behavior, transcript recovery, self-improvement compatibility and current regression evidence. Identify the exact next package/regression obligation and forbid claiming packaging that has not occurred.

## P31 — Portfolio Scheduler / Blocked-Frontier Parallelism
Audit the portfolio queue under a real Founder decision gate. Distinguish blocked active project work from independent authorized R&D, audio-preflight and system maintenance. Design a scheduler that does not bypass Founder lock/canon decisions but also does not idle the whole studio when safe independent branches exist. Respect WIP guard and Story First priority.

## P32 — Integrated Red Team / Next-Generation Roadmap
Integrate P01–P31. Rank defects and opportunities by FATAL/MAJOR/MEDIUM/POLISH, recurrence, impact on completed story/audio, implementation cost, reversibility and evidence quality. Reject duplicate ideas. Produce the smallest coherent improvement roadmap and derive exactly two next-generation prompts from each completed prompt: one implementation prompt and one independent validation prompt.
