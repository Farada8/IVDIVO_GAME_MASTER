# G01–G32 SYNTHESIS + ROADMAP

## Executive conclusion
The system no longer needs broad prompt multiplication as its primary improvement strategy. The highest-value frontier is now **promotion discipline + real pilots + evidence integrity + durable project recovery**.

The sprint found that many useful mechanisms already exist as specs. The next quality jump comes from making a smaller number executable, testing them against current production, and refusing to promote anything whose evidence class is weaker than its claim.

## What materially improved in this sprint

### 1. Project resumability moved from aggregate labels to durable evidence
Created exact project-state pointers for:
- D03 BODYGUARD FOR THE FALLEN IDOL;
- D05 NINETY MISSING MINUTES;
- IVDIVO BOOK 1 LESSON ZERO.

Updated PROJECT_STATES coverage index to v1.1.

D06/D07/D08 remain explicit gaps instead of guessed state. This is a success: the system now records uncertainty rather than manufacturing continuity.

### 2. Evidence boundaries became executable
A single evidence validator now demonstrates the required firewalls across writing, audio and reference research:
- engineering PASS cannot become literary PASS;
- AI review cannot become Human Signal;
- dry run cannot become live provider evidence;
- story gate cannot become Founder lock;
- source checksum cannot become full read.

This is a high-leverage universal mechanism because the same category error appeared repeatedly across story, audio, research and self-improvement work.

### 3. Story Core moved from labels to causal assertions
The deterministic validator rejects a formally complete but non-causal core. It specifically tests protagonist agency, price, midpoint change, causal climax choice, external rescue and causal edge presence.

It is **not yet ready for universal promotion** because its fixtures were authored by the same system. It needs real-project regression and independent blind calibration before thresholds become authority.

### 4. Concurrency safety was reduced to a testable invariant
The core law is small:
`BASE REVISION -> WRITE -> REVISION ADVANCES -> STALE SECOND WRITE MUST FAIL`.

Independent branches can proceed only when their dependency keys do not collide and they converge through readback/reconciliation.

### 5. SI-0008 exposed the correct repair architecture
The defect is real, but manually replacing a large minified registry would be fragile. The better systemic fix is not “edit one JSON harder”; it is:
`REGISTER-CANDIDATE COMMAND -> SCHEMA -> SEMANTIC DEDUPE -> SNAPSHOT -> ATOMIC WRITE -> INVARIANT -> READBACK -> ROLLBACK`.

That prevents future registry/state drift for every candidate.

### 6. Transcript recovery reached a real evidence boundary
A genuine large ROOM917/engine conversation export was located, but current File Library tooling did not provide executable full bytes. The system correctly stopped. This validates the transcript-recovery doctrine: source discovery is not ingestion; snippets are not a complete transcript; recovered text is not current authority.

## Path to the goal
The goal is a studio that reliably produces **stronger completed books -> locked story -> high-quality audio -> release evidence -> learning -> portable verified improvement**, with low repeated manual reconstruction.

Recommended control loop:
1. Restore exact persisted project state.
2. Select one real production failure/gap.
3. Choose the earliest responsible layer.
4. Apply the smallest candidate mechanism.
5. Run deterministic negative/positive tests.
6. Pilot on a current project where text protection permits it.
7. Obtain independent/human/provider evidence only where that evidence class is actually required.
8. Promote or reject.
9. Write through GitHub + Drive and read back.
10. Prune duplicate meta-work and return to book/audio production.

## Recommended next bounded tranche
Do **not** auto-run H01–H64. After a fresh-main check, start with:
`H01 -> H02 -> H03 -> H05 -> H09 -> H13/H14/H15 -> H19/H20`.

If atomic SI mutation cannot be implemented in the current tool surface, switch immediately to the highest independent production-safe task instead of waiting.

## Stop rule
Stop/defer a meta task when:
- the target gate is already closed by newer main;
- exact source/authority is unavailable;
- the mechanism duplicates a current control;
- real product pilot has higher information value;
- independent/human/provider evidence is required and unavailable;
- another prompt would only create a new schema without changing a decision;
- meta-work begins starving actual book/audio production.

**FINAL SYNTHESIS:** fewer new systems, more verified transitions from candidate -> pilot -> evidence -> promotion -> production result.
