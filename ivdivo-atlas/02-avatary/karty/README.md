## Реестр

`REESTR.csv` — таблица различения. Строка на карту, колонки на все параметры.

Реестр существует ради одной задачи: **совпадения ловятся механически, а не на глаз**. Сортировка по ключу, поиск дублей — и видно сразу.

Порядок работы: **сначала строка в реестре, потом карта**. Не наоборот. Если параметры назначаются после написания, они подгоняются под уже сочинённое, и весь смысл теряется.

Проверка на дубли:

```bash
python3 -c "
import csv,collections
r=list(csv.DictReader(open('REESTR.csv')))
k=lambda x:(x['yarus'],x['stavka'],x['domen'],x['registr'],x['sreda'],x['moment'],x['kadr'])
c=collections.Counter(k(x) for x in r)
for key,n in c.items():
    if n>1: print(n,key)
"
```

Пусто на выходе — совпадений нет.

## Шаблон

`SHABLON.md` — структура карты. Копируется под новый номер и заполняется.

Обязательные разделы: документальное ядро · параметры различения · производственный визуальный замок · Face-ID · аналитический разбор · костюм · среда · инструмент · огнеобраз · композиция · свет · готовый промт · негативный блок.

---

## Правило разметки

Как во всём корпусе: **[И]** источник ИВДИВО · **[С]** внешний источник · **[Р]** реконструкция.

Документальное ядро — только [И], дословно, без изменений. Всё остальное в карте — художественно-исследовательская модель, и это должно быть сказано в самой карте, а не подразумеваться.

Термины без установленного определения (натическое тело, плотическое тело, реалическое тело, зерцала) сохраняются дословно и **не расшифровываются**. Допустима ограниченная аналогия с прямым указанием, что она не является определением.

## Квоты

Различение держится на квотах, а не на вкусе. Без них правило против одинаковости само становится одинаковостью — как уже случилось с телосложением в картах 38–40.

| Ось | Значений | На 384 карты |
|---|---|---|
| Ярус мира | 6 | по 64 |
| Уровень ставки | 7 | 1–2: ~96 · 3–4: ~192 · 5–7: ~96 |
| Домен занятия | 9 | по ~43 |
| Конструктивный регистр | 14 | по ~27 |
| Средовая логика | 10 | по ~38 |
| Тип кадра | 8 | по 48 |
| Возраст | 4 | 20–30: 60 · 35–50: 150 · 50–65: 120 · 65+: 54 |
| Сложение | 4 | по 96 |

**Ни один параметр не повторяется в трёх подряд идущих картах.**

## Объём

Полная карта — около шести тысяч слов. На 384 карты это два миллиона, работа не на один год.

Принято: **40–60 карт полностью** как образцы, остальные — короткая спецификация на страницу. Спецификация содержит документальное ядро, строку реестра, Face-ID и готовый промт. Без аналитического разбора.

Полные карты помечаются в реестре статусом `full`, спецификации — `spec`.

## Картинки

**В git не кладутся.** Бинарные файлы раздувают историю необратимо: один раз добавленный файл остаётся в репозитории навсегда, даже если его удалить.

Готовые изображения хранятся отдельно — облако, диск, Git LFS. В карте указывается только имя производственного файла, как и сейчас:

```
0038_AVS_P038_Nisa_Nit-Sinteza_v01_WIP.png
```

Папка `materialy/` — для текстовых материалов к картам: выписки, наброски, ссылки.
