## 1. Continuation is default

Once the Founder has given a clear instruction to work/continue a project, do **not** require repeated `и / дальше / продолжай` messages between consecutive executable steps.

Continuation words remain valid shorthand, but are not a prerequisite.

Within the active task, continue through all **SAFE + ZERO-COST + REVERSIBLE + TOOL-EXECUTABLE** unblocked obligations until a real stop condition is reached. Do not stop merely because one artifact has been completed when the next obligation is already resolved and executable.

Do not claim background work while no turn/tool execution exists. Across chats, continuity is achieved by restoring persisted execution state and authority.

Before any resumed/new production work:

1. Read the current Drive root router.
2. Read the active project's `CURRENT_EXECUTION_STATE` or equivalent newest status artifact.
3. Inspect newer relevant Drive/GitHub artifacts and recent repository deltas since `last_completed_artifact`.
4. Restore source/version/hash, branch, delivery mode, overlay, voice/acoustic locks, open gates and blocker.
5. Use Project/past-chat context only to fill continuity not already persisted.
6. Use File Library books/craft sources as `REFERENCE ONLY`.

   `CURRENT_AUTHORITY -> ACTIVE_PROJECT -> ACTIVE_BRANCH -> BUILD_ID -> LAST_COMPLETED_ARTIFACT -> OPEN_GATES -> BLOCKER -> HIGHEST_UNBLOCKED_NEXT_OBLIGATION`.
8. Execute the highest unblocked obligation immediately when safe and tool-executable.

A newer valid persisted state wins over stale conversational context.

## 5. Reusable voice-audition/performance gate

Generic mechanism upstreamed from newer project work:

- loudness-match candidates;
- music/reverb/heavy processing OFF during voice selection;
- anonymize labels where practical;
- never cast from one impressive line;
- require `NATURAL_RESTRAINED` + `DIRECTED_CHANGE` takes;
- test response to one precise playable direction;
- define role-specific `HARD_FAILS`;
- use functional blocks testing distinct pressures/registers;
- lead pair/chemistry test without forcing romance;
- 8–10 minute long-form fatigue/listenability test before season lock;
- headphones + mono + phone/device translation;
- provisional lock only after threshold + no hard fail + direction-change PASS;
- season lock only after required performed long-form/multi-episode evidence.

Project-specific thresholds/roles must be rebound through the project overlay.

## 6. Reference-book mechanisms upstreamed

`REFERENCE ONLY` abstractions used by applicable prompts/engines:

- **Dialogue/performance:** voice/dialogue is action under pressure; test want, resistance, subtext, said/unsaid/unsayable, listening and pause rather than pleasant timbre alone.
- **Sound design:** sound/music/perspective/texture arise from story and character change; performance rhythm can drive edit/sound timing; proximity and near/mid/far perspective are dramaturgical information.
- **Story causality:** production checklists never replace internal story causality; technically complete scenes still fail if desire/opposition/turn are absent.
- **Suspense/listener contract:** preserve emotionally meaningful unresolved questions; sound/music must not reveal answers early.
- **Reference governance:** newest valid version first; older versions `SUPERSEDED/REFERENCE ONLY`; never rebuild an engine merely because the active chat cannot immediately see it.

- unresolved authority/source/branch ambiguity;
- missing real evidence or required human listen;
- unavailable paid/authenticated provider execution;
- user-side credential/API-key action;
- irreversible/high-impact external action requiring explicit approval;
- voice/canon/release lock gate requiring evidence/approval;
- missing tool/capability;
- explicit Founder `STOP/HOLD`.

At a stop, report the exact blocker and exact next action. Do not manufacture extra documents to simulate progress.
