## Mechanism extraction rule
Do not store vague summaries such as “book teaches composition”. Extract executable mechanisms, for example:
- dominant/subordinate mass hierarchy;
- viewing-distance legibility;
- figure-group rhythm;
- one-point / multi-point perspective conditions;
- FOH/BOH conflict patterns;
- minimum functional clearances from authoritative technical references;
- lighting layers by function;
- material-weather compatibility;
- maintenance and replacement implications.

Every mechanism must state where it applies and where it does not.

## Copyright and provenance policy
Raw copyrighted sources remain private in Drive when the user has provided them. GitHub contains only metadata, short derived mechanism statements, schemas, tests, provenance pointers and original engine outputs. Public-domain sources may later receive a different storage policy, but only after copyright/public-domain status is checked rather than assumed.

## Ingestion sequence for new books
`UPLOAD -> integrity check -> file identity -> canonical work -> discipline tag -> source passport -> mechanism extraction -> conflicts/limits -> fixture -> K-grade -> project-stage router -> regression test -> readback`.
