# CYCLE5 — ANALYSIS / SYNTHESIS / PATH TO GOAL

## 1. What changed after Cycle5
The business system is no longer blocked by lack of ideas. It is blocked by the transition:

`PUBLIC SIGNAL -> USEFUL ARTIFACT -> REAL BUYER USE -> PAYMENT -> REPEATABILITY -> UNIT ECONOMICS -> SCALE`.

Cycle4 established many plausible markets. Cycle5 proves the next engineering layer must improve evidence quality rather than expand the opportunity count.

## 2. Portfolio decision
### PRIMARY — procurement decision intelligence
Retain.

Why it is structurally strongest at current evidence level:
- public source stream is large, recurring and deadline-driven;
- buyer work is naturally repeated;
- native portal search leaves room for cross-source normalization, dedupe, capability mapping, fatal-unknown handling and decision queues;
- public artifact can be built with €0 new founder cash;
- every missed/reviewed tender gives a future measurable event.

But do not claim product-market fit. Supplier profile, actual user workflow and WTP remain unproven.

### PILOT — retrofit qualification / route exceptions
Retain, narrowed.

Do not compete with One Stop Shops on generic full-project coordination. Potential differentiated layer is before/around the formal provider journey:
- route triage;
- traditional-home exception routing;
- grant/cash-timing readiness;
- provider-fit matrix;
- missing-document/fact checklist;
- staged vs whole-house decision support.

### PILOT — SME AI workflow implementation readiness
Retain, narrowed.

Generic “digital/AI diagnostic” is weak because Digital for Business already subsidises core diagnosis. Potential differentiated layer:
- sector-specific workflow evidence;
- implementation backlog;
- integration/control/data map;
- post-Digital-for-Business execution preparation;
- measurable baseline/falsifier;
- vendor/configuration readiness for a concrete job.

## 3. Business Engine improvement
The engine should now treat `FREE_OR_SUBSIDISED_SUBSTITUTE` as a first-class competitor, not a footnote. A good business opportunity can fail because the same job is already supplied by a public programme, platform, OSS, consultant network or mandated portal.

New core path:
`JOB -> NATIVE/FREE SUBSTITUTE -> RESIDUAL UNSOLVED JOB -> ARTIFACT -> DECISION DELTA -> BUYER TEST`.

This is stronger than `market size -> idea -> build`.

## 4. Knowledge-library conclusion
The current 78-file business library is sufficient for the next evidence stage. More generic business-book ingestion has lower VOI than proving artifact usefulness.

Highest-value existing mechanism families already cover:
- lean experiments / pretotyping / Mom Test;
- positioning / sales;
- business-model design;
- customer funding / acquisition;
- finance / valuation;
- systems / constraints / flow;
- measurement / decision quality;
- failure / complexity.

Future library additions require a specific unresolved mechanism gap, not “more books = better engine”.

## 6. Path to an actually useful business
### Gate A — artifact completeness
Automate/standardize public-source ingestion and produce repeatable artifacts from fresh data.

### Gate B — independent utility
Have a recipient-like reviewer use the artifact against a named decision and record before/after decision, missing fields and failure cases. This is still not WTP.

### Gate C — smallest real buyer evidence
When outreach is permitted, ask a narrowly defined buyer to use the artifact on a real task. Measure use, requested changes, recurrence and whether they would commit time/data/money.

### Gate D — payment proof
Only after a concrete commitment/payment may WTP move beyond null.

### Gate E — repeatability / unit economics
Repeat across buyers and periods; measure acquisition effort, delivery time, data cost, gross margin, retention/renewal and failure rate.

### Gate F — scale or kill
Scale only if recurring value and economics survive. Otherwise narrow, change route (CREATE/BROKER/ACQUIRE), or kill.

## 7. Immediate next frontier
