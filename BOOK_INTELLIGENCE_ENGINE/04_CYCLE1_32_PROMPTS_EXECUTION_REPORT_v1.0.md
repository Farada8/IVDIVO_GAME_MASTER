## Architecture mechanisms extracted at design level

These are architecture decisions supported by the inspected foundation and existing IVDIVO evidence. They are not claims that every named book has been fully read in this cycle.

1. **Stable source identity + rights/provenance:** source bytes, source identity, evidence group and permission state must be separate.
2. **Lifecycle truth:** indexed/searched/TOC-mapped/partial-read/full-read/synthesized are distinct states.
3. **Structure before indiscriminate extraction:** chapter/part/concept topology reduces blind corpus processing.
4. **Claim + locator binding:** source-derived decisions must be traceable to where the claim came from.
5. **Mechanism abstraction:** reusable knowledge is a project-neutral mechanism, not copied expression.
6. **Failure-mode capture:** store when a rule fails, not only when it works.
7. **Contradiction + evidence independence:** two books can disagree; duplicate mirrors are not corroboration.
8. **Semantic dedupe:** repeated mechanisms collapse to one semantic cluster without evidence inflation.
9. **Provenance graph:** keep backward/forward lineage from source to engine rule.
10. **Problem-targeted retrieval:** retrieve only likely decision-changing material; do not reread the whole library by default.
11. **Retrieval evaluation != output validation:** finding the right source is separate from improving the real product.
12. **Relevance feedback with lineage:** project results may improve retrieval ranking without rewriting source claims.
13. **Domain AdapterPacket:** Story/Audio/Business/etc. consume typed mechanisms, not raw book blobs.
14. **Verification != validation:** schema/unit-test correctness cannot prove better story/business/audio.
15. **Real two-project promotion path:** one successful application is evidence; universal rule requires replication or stronger explicit evidence.
16. **Configuration + decision lineage + write-through:** accepted learning must reach router/config/prompt/test/current state and survive readback.
